# 技能包规范

新增或修改技能包时按本规范执行。`tools/validate_skills.py` 会检查其中的硬性项。

---

## 1. 命名

- 目录名 = `<组>-<科目号>-<英文名>`，全小写、连字符分隔
- 组：`z`（资产）/ `f`（负债）/ `s`（损益）/ `a`（通用）
- 例：`z-1-2-bank-deposits`、`f-9-taxes-payable`、`s-14-credit-impairment`
- 辅助分析类用具名：`doc-ocr-extract`、`financial-statement-analysis`

## 2. SKILL.md

**frontmatter（必需）**：

```yaml
---
name: z-1-2-bank-deposits        # 必须与目录名一致
description: 一段话说明何时使用    # 含触发场景与触发词
version: 1.0.0
---
```

**正文必需章节**：

| 章节 | 内容 | 被谁消费 |
| --- | --- | --- |
| 技能来源与使用声明 | 归属、许可、免责 | 首次调用时逐字输出 |
| 六要素 | 审计目标 / 所需资料 / 所需数据 / 核对逻辑 / 底稿内容 / 输出格式 | agent 理解任务边界 |
| 程序分派表 | 标准 Markdown 表格，列：程序卡 / 程序名称 / 程序库来源 / 对应认定 / 执行方式 / 产出底稿 | 决定执行哪几张卡 |
| 一级复核清单 | 交付前逐项自查 | 质量门 |
| 边界与易错点 | 什么不做、常见错误 | 防越界 |
| 验证要点 | 如何判断结果可信 | 复核 |

**程序分派表必须是标准 Markdown 表格**。解析器靠它确定程序卡清单，表格格式错会导致程序卡识别为 0。

## 3. dsl.json

```json
{
  "skill": "z-1-2-bank-deposits",
  "procedures": [
    {
      "id": "P01",
      "name": "银行存款余额明细表编制",
      "source": "Z1002 程序1",
      "assertions": ["C", "E", "A"],
      "mode": "hybrid",
      "human": false,
      "tools": ["excel_read", "recalc_check"],
      "output": "Z-1-2-01"
    }
  ]
}
```

- `assertions`：认定编码 `E` 存在性 / `C` 完整性 / `A` 准确性 / `V` 计价 / `P` 列报
- `mode`：`auto` 全自动 / `hybrid` 自动+人工 / `manual` 人工主导
- `human: true` 时 agent 只准备资料，不代替判断
- `tools` 为确定性工具标识，须与运行时注册的工具一致

## 4. 程序卡文档

路径：`procedures/P01-<名称>.md`

必需小节：

- **输入**：需要哪些资料、哪些字段
- **步骤**：可执行的动作序列
- **质量门**：什么条件下算通过（不通过要升级）
- **升级路径**：缺数据 / 有差异 / 超出判断范围时怎么办

## 5. 底稿制式

所有产出底稿必须遵循 `skills/auditox-wp-standard/SKILL.md`：

1. 一、项目基本信息
2. 二、审计目标和程序说明
3. 三、审计程序执行结果
4. 四、审计说明

**副本先行**（先复制模板再填）+ **修订记录**（每次改动留痕）。

资料不足以支撑四段式时，用三段式兜底：审定表 / 明细表 / 凭证抽查表。

## 6. 更新记录

`CHANGELOG.md`，倒序表格：

```markdown
# 更新记录 · 银行存款

| 更新日期 | 更新内容 |
| --- | --- |
| 2026-10-01 | 新增 P10 披露检查；修正 P04 调节表勾稽口径 |
| 2026-09-23 | 首次发布 |
```

只记技能内容变更，不记分发渠道动作（上架、打包、上传等）。

## 7. 版本号

| 变更 | 版本 |
| --- | --- |
| 修错别字、调表述 | patch |
| 新增程序卡 / 模板 / 工具映射 | minor |
| 改结构、断后向兼容 | major |

## 8. 提交前自检

```bash
python tools/build_index.py
python tools/validate_skills.py
```

两项通过再提交；CI 会跑同样的检查。
