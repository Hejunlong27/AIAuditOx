# 财务数据包与项目数据库架构

## 结论

可行，而且适合作为审小牛后续所有审计模块的统一底座。关键不是“把 Excel 放进数据库”，而是建立一条可追溯的数据链：

```text
原始数据包（SJC / Excel / CSV / PDF / 扫描件）
  → 原始层（不可变文件 + SHA-256）
  → 暂存层（工作表、单元格、行级导入记录）
  → 标准账套层（公司、期间、科目、凭证、分录、余额、往来单位）
  → 审计项目层（重要性、程序、样本、底稿、发现、调整、函证、复核）
  → 证据与数据血缘层（每个金额回到来源文件和行）
```

## 推荐技术形态

- **SQLite**：每个审计项目一个本地数据库，适合单机、可备份、可加密卷存放，事务和审计轨迹清晰。
- **DuckDB（可选）**：只用于大账套的分析查询和列式汇总；SQLite 仍是项目事实库。
- **原始文件仓**：按项目保存原始 SJC、Excel、CSV、PDF、图片和解析产物，不覆盖原文件。
- **字段映射注册表**：将不同财务软件的列名映射到统一会计模型，映射规则可版本化、可复核。
- **确定性计算引擎**：借贷平衡、科目勾稽、账龄、抽样、比率、期望值、汇总和跨表核对不交给模型。
- **Agent 工具层**：模型只能通过受控工具读取项目数据库、生成分析建议和起草底稿。

## 统一会计模型的最小实体

```text
company / project / period
account / opening_balance / period_balance
voucher / voucher_entry
party / contract / invoice / bank_statement
document / evidence / workpaper / finding / adjustment / confirmation
materiality / audit_procedure / sample / review_note
```

## 模块落地顺序

1. 数据包导入与原始文件登记；
2. 列映射、科目映射和导入校验；
3. 科目余额表、总账、明细账、凭证查询；
4. 分析性复核、勾稽检查、账龄和抽样；
5. 底稿生成与金额数据血缘；
6. 函证、调整分录、报告和项目复核；
7. 经营分析与跨期比较。

## 安全与保密

- 客户数据默认只在本机项目和本地模型服务中流转。
- 文件导入使用路径白名单，拒绝目录穿越和未确认的外部访问。
- 每个原始文件、映射版本、计算任务和底稿版本保留摘要与来源。
- 模型输出标记为“分析草稿”，不得替代原始证据、确定性计算或项目组结论。
- 云 API 必须由用户显式配置；未配置时完全使用本地模型或离线规则。

## 本地模型建议

- 轻量笔记本：Qwen3.5 2B / 4B，优先保证可运行和中文底稿草稿。
- 主流 16 GB 笔记本：Qwen3.5 4B / 9B，按内存与显存推荐。
- 视觉识别：Qwen2.5-VL 3B 起步；复杂票据或 32 GB 以上设备考虑 7B。
- 模型目录、下载状态和硬件适配由本地 Harness 检测，不在前端写死单一模型。
- Ollama 一键拉取和国内镜像检索必须明确区分，避免误导数据来源。
