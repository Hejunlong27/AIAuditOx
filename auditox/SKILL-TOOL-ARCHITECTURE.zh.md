# Skill × Tool 融合架构

## 一句话

**Skill 负责审计程序的判断逻辑，Tool 负责确定性的执行能力，Runtime 负责保存事实，Trace 负责证明过程。**

## 1. 融合原则

上一版 Runtime 解决的是“审计程序如何被执行、如何形成底稿”；当前 Harness 解决的是“Agent 如何组织对话、调用工具、加载技能、管理本地模型和复用插件”。融合不是把两套界面拼在一起，而是把两者拆成稳定的四层：

```text
Skill 定义程序
   ↓
Agent 编排任务并选择工具
   ↓
Tool 执行文件、数据、计算、OCR、文档和模型操作
   ↓
Runtime + Trace Ledger 保存事实、证据、底稿与可核验留痕
```

## 2. Skill 的边界

Skill 是可版本化、可审阅的审计程序包，必须说明：

- 适用科目、认定、审计目标和适用范围；
- 输入资料、字段口径和必需前置条件；
- 执行步骤、判断规则、阈值和异常处理；
- 需要的工具能力和数据接口；
- 证据要求、底稿结构、复核点和禁止事项；
- 输出契约：确定性计算结果、模型建议、待补资料、待复核事项。

Skill 不应把关键金额、勾稽结果和审计结论交给模型自由生成。

## 3. Tool 的边界

Tool 只执行明确、可测试、可替换的动作：

- 文件读取、表格解析、账套导入和字段映射；
- 数据库查询、汇总、勾稽、抽样和确定性计算；
- OCR、合同/发票/票据识别、图像预处理；
- Word/Excel/PDF 生成、底稿写入和文件摘要；
- 本地模型调用、远程模型调用和 MCP 调用；
- 项目、审批、证据、版本和留痕操作。

Tool 不宣称审计结论；它返回结构化结果、失败原因、证据引用和是否需要人工复核。

## 4. 旧版 Runtime 的延续

旧版 `agent-runtime` 继续承担：

- 项目、资产、任务、计划、审批、证据和底稿存储；
- 审计程序执行、质量门和人工复核；
- 确定性工作底稿生成及 SHA-256 文件摘要。

Harness 通过 `tool-auditox-runtime` 桥接这些能力，并新增统一 Trace Ledger。旧版内容保存在 GitHub 分支：

```text
archive/legacy-runtime-92e03237
```

## 5. 新能力

### 统一 Trace Ledger

`packages/extensions/tool-auditox-runtime/src/trace.ts` 为工具调用追加 JSONL 记录，包含：

- 项目、任务、技能和工具身份；
- 输入摘要和输出摘要；
- 成功/失败状态；
- 上一条记录哈希和本条记录哈希。

这使底稿不仅能看到“最终文件”，还能看到“谁在什么时候用什么工具、基于什么输入生成了它”。底层 Runtime 的工作底稿本身继续包含程序明细、证据清单、修订记录和文件摘要。

### MCP 能力层

`packages/extensions/auditox-local-services/src/mcp.ts` 在回环地址暴露 MCP 工具，让其他 Agent 可以调用审小牛的技能、项目、底稿和留痕能力，详见 [MCP.zh.md](./MCP.zh.md)。

## 6. 后续扩展规则

新增一个审计能力时按以下顺序设计：

1. 先写 Skill，明确审计程序逻辑和输出契约；
2. 再判断能否复用现有 Tool；
3. 不能复用再新增 Tool，并为 Tool 定义输入、输出、错误和证据；
4. 通过 Runtime 持久化结果；
5. 通过 Trace Ledger 记录执行链；
6. 需要跨 Agent 复用时，再暴露为 MCP Tool。

这条路线保证审小牛不会退化成“一个会聊天的审计界面”，而是逐步成为可组合、可复核、可被其他系统调用的审计能力基础设施。
