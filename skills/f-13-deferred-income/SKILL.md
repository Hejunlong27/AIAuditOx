## 六要素（技能工厂确认记录）

| 要素 | 内容 |
|------|------|
| 审计目标 | 完整性（C）：所有递延收益均已记录（含未列示于账面者）；存在（E）：记录的递延收益于资产负债表日存在且归被审计单位拥有或控制；准确性（A）：金额正确计算、适当加总且准确记录；计价（V）：按恰当金额计价（含减值、摊销、公允价值等调整）；列报（P）：分类、披露恰当 |
| 所需资料 | 递延收益明细表与明细账、政府补助批准文件与收款凭证、摊销政策与摊销计算表、首次接受委托时的年初余额资料、合同负债明细账、销售合同（含履约义务与收款条款）、预收款项明细、收入确认进度表、报表附注 |
| 所需数据 | 各补助项目期初与期末余额、本期增加额与摊销额、摊销年限、补助性质（与资产相关或与收益相关）、预期摊销额、合同金额与已收款金额、已履约金额、应确认合同负债金额、实际执行的重要性水平 |
| 核对逻辑 | 1. 实质性分析程序（将实际值与预期值进行比较。）；2. 递延收益明细表编制与核对（获取或编制递延收益明细表，复核加计正确并与总账数、报表数和明细账合计数核对是否相符。）；3. 递延收益余额抽样与追溯检查（抽样检查递延收益余额）；4. 合同负债完整性检查（检查合同负债完整性）；5. 递延收益披露检查（审计递延收益的披露） |
| 底稿编制内容 | 见「产出清单」，全部底稿采用四段式制式：底稿名称与表头（项目基本信息）→ 审计目标和程序说明 → 审计程序执行结果 → 审计说明。共 5 张底稿。 |
| 输出格式 | xlsx 工作簿（模板见 templates/F-13递延收益审计工作簿模板.xlsx），每份底稿同路径伴随「底稿名称+修订记录」.md |

## Steps（助理调度流程）

1. 确认项目工作目录已由项目经理指定（未指定则拒绝启动，升级项目经理）；在 `02_工作底稿/F-13递延收益/` 下基于模板创建工作簿副本。
2. 校验输入资料完整性（见六要素「所需资料」）；缺失时向项目经理列明缺口清单并挂起。
3. 按依赖顺序分派实习生程序：P01 → P02 → P03 → P04 → P05；人工程序标记待办并跟踪完成状态。
4. 每个程序卡执行遵守「副本先行」：修改任何既有底稿前先创建副本入 `.auditox_backups/`；底稿每次生成/修订同步更新同路径「底稿名称+修订记录」.md。
5. 异常激活：按各程序卡「升级路径」处理，发现异常事项逐级升级。
6. 汇总各程序卡产出至工作簿，执行一级复核（见下方复核清单），复核通过后提交人工二级复核。

## 一级复核清单（助理执行，独立于编制上下文）

- 完整性：P01~P05 计划实施的程序均有底稿或「不适用+理由」记录；索引号连续无缺。
- 勾稽：明细表合计数 = 总账数 = 报表数；底稿间交叉索引正确。
- 证据充分性：每项结论可回溯到数据源；差异事项均有解释与支持文件。
- 异常闭环：所有异常事项有处理结果记录；未回函/回函差异已实施替代程序。
- 制式合规：每张底稿四段式结构完整，表头七要素齐全，修订记录同步。

## 边界与禁止事项

- 允许操作范围：仅项目工作目录内文件；仅调用 file_ops（读/写/改/格式）、数据核对脚本、Excel 计算。
- 禁止：物理删除任何文件（删除一律移入可恢复区）；向项目目录外发送客户数据；代替人工执行函证寄发/跟函/监盘动作；修改原始资料目录（01_原始资料 只读）；跳过强制程序。
- 数字核对一律使用脚本精确匹配，禁止以模型估算代替；差异原因说明可用模型起草，但必须标注「待人工确认」。

## Pitfalls

- 与资产相关的政府补助应冲减资产账面价值或确认为递延收益并在资产使用寿命内分期计入损益；与收益相关的补助用于补偿以后期间费用的才计入递延收益，分类错误会导致摊销方法与年限错误
- 摊销进度应与补助文件约定的受益期间一致，过快或过慢都须查明
- 首次接受委托时年初递延收益必须追溯查验，入账依据不充分的年初余额会影响期初余额的可依赖程度
- 递延收益与合同负债是两个不同性质的科目（前者是政府补助，后者是已收未履约的合同款），勿混用
- 合同负债与预收款项的划分应按准则判断，错误划分会导致列报错报
- 已满足确认条件的补助未及时摊销会虚增负债并低估损益
