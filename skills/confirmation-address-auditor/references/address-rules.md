# 地址标准化与匹配规则库

## 一、企业名称标准化

### 1.1 处理步骤

1. **全角转半角**：`（Ａ）` → `(A)`，全角空格 → 半角空格
2. **去噪**：删除空白、换行、连字符、各类中英标点（`·—/，。()【】《》` 等）
3. **组织形式归一**：`有限责任公司` / `股份有限公司` → `有限公司`（`full_unified`）
4. **字号提取**：剥离组织形式词得到 `core`
5. **行政区划前缀剥离**：得到 `core_na`（用于识别简称）

### 1.2 组织形式词表（按长度倒序剥离）

```
有限责任公司 股份有限公司 集团有限公司 有限合伙企业 合伙企业
有限公司 分公司 子公司 控股 集团 有限责任 有限 责任 股份 个体 工商户
公司 厂 中心 研究院 研究所 事务所 商行 经营部 门市部 商店 超市 酒店 宾馆
```

### 1.3 相似度判定

| 条件 | 相似度 | 结论 |
|---|---|---|
| `full` 完全一致 | 1.00 | 名称完全一致 |
| `full_unified` 一致 | 0.99 | 组织形式表述差异，实质一致 |
| `core_na` 一致 | 0.97 | 仅行政区划前缀/组织形式表述差异 |
| `core_na` 互为包含 | 0.90 | 疑似简称或名称不完整 |
| 字符相似 ≥ 0.75 | 原值 | 高度相似但存在用字差异，需人工确认 |
| 其他 | 原值 | 实质性差异 |

> 触发中风险 M3 的阈值：`name_sim < 0.95`，或未提供 `registered_name`。

## 二、地址标准化

### 2.1 处理步骤

1. 全角转半角 → 去噪
2. **同义词转换**（长词优先）

   | 原文 | 归一为 |
   |---|---|
   | 高新技术产业开发区 | 高新区 |
   | 经济技术开发区 / 经济开发区 | 开发区 |
   | 工业园区 | 工业区 |
   | 科技园区 | 科技园 |
   | 居民委员会 | 居委会 |
   | 中国（前缀） | 删除 |

3. **中文数字归一**：`一路 / 一号 / 三层 / 五栋` → `1路 / 1号 / 3层 / 5栋`
   （仅作用于 号/栋/幢/座/室/层/楼/单元/弄/区 语境，避免误伤"三一重工"等字号）

### 2.2 地址分层解析（`parse_address`）

```
[省/自治区/直辖市/特别行政区] → [市/自治州/地区/盟] → [区/县/新区/旗/县级市] → 详址
详址 → 道路 | 门牌号 | 楼栋 | 房号/楼层
```

| 元素 | 抽取规则 | 示例 |
|---|---|---|
| province | `^(.{2,8}?(省\|自治区\|特别行政区))`，或匹配 34 个省级行政区全称/简称 | 湖南省 / 内蒙古自治区 |
| city | `^(.{2,8}?(市\|自治州\|地区\|盟))` | 长沙市 / 湘西自治州 |
| district | `^(.{2,10}?(新区\|区\|县\|旗\|市))` | 岳麓区 / 浦东新区 / 长沙县 |
| road | `…(大道\|大街\|大路\|路\|街\|道\|巷\|弄\|里\|村\|镇\|乡\|屯\|工业区\|开发区\|科技园)`，前缀惰性匹配 | 麓谷大道 / 芙蓉中路 |
| door | `\d+(-\d+)?号` | 627号 |
| building | `\d+号楼\|栋\|幢\|座\|[A-Za-z]座\|\d+期` | A座 / 3号楼 |
| room | `\d+室\|层\|F\|单元\|楼` | 2201室 / 3楼 |

> 解析不出任何有效元素时 `parseable = False`，触发高风险 H2。

## 三、三级匹配

### 3.1 一级：字符串精确匹配

标准化后整体字符串完全一致 → 判定"一致"，匹配度 100。

### 3.2 二级：语义相似度匹配

```
匹配度 = 100 × ( 0.45 × 序列相似度 + 0.30 × 二元组Jaccard + 0.25 × 行政区划层级得分 )
```

- **序列相似度**：`difflib.SequenceMatcher` 对归一化全文求比
- **二元组 Jaccard**：地址切分为「数字+单位 token」与「中文二字滑窗」，取交集/并集比
- **行政区划层级得分**：省/市/区县逐级比对命中率；双方均缺失时取 0.5

**行政区划冲突上限**（防止详址巧合造成误判）：

| 冲突层级 | 匹配度上限 |
|---|---|
| 省级冲突 | 35 |
| 市级冲突 | 55 |
| 区县级冲突 | 75 |

### 3.3 判定阈值

| 匹配度 | 匹配结果 |
|---|---|
| ≥ 95 且无行政区划冲突 | 一致 |
| 80 ~ 95 | 基本一致 |
| 60 ~ 80 | 部分一致 |
| < 60 | 不一致 |
| 任一方地址缺失 | 无法比对 |

### 3.4 三级：企业信息合理性

| 校验项 | 方法 | 命中规则 |
|---|---|---|
| 名称一致性 | `entity_similarity` vs `registered_name` | M3 |
| 信用代码校验 | GB 32100-2015 校验位算法 | M4 |
| 电话区号一致性 | 区号库比对地址城市（函证地址优先，缺失回退注册地址） | M5 |
| 函证类型匹配 | 银行函证 ↔ 名称含金融机构特征词 | M6 |
| 一址多照 | 注册/函证地址聚簇，同一地址对应 ≥ 3 个不同主体 | H3 |
| 投递点颗粒度 | 函证地址可解析但无门牌号 | M7 |

## 四、逐项差异比对（`element_diff`）

把「被审计单位提供的询证信息」与「工商登记信息」拆成八个可比对项目，逐项输出原文取值与判定：

| 序号 | 比对项目 | 取值来源 | 判定规则 |
|---|---|---|---|
| 1 | 公司名称 | `entity_name` vs `registered_name` | 相似度 ≥ 0.95 判一致（复用 `entity_similarity`） |
| 2 | 省份/直辖市 | `parse_address().province` | 相等或互为前缀即一致 |
| 3 | 地级市/自治州 | `.city` | 同上 |
| 4 | 区/县 | `.district` | 同上 |
| 5 | 道路/街道 | `.road` | 同上 |
| 6 | 门牌号 | `.door` | 同上 |
| 7 | 楼栋 | `.building` | 同上 |
| 8 | 房间/楼层 | `.room` | 同上 |

**三种判定状态**（对应 `same` 字段）：

| 状态 | `same` | 触发条件 |
|---|---|---|
| 一致 | `true` | 双方取值相等或互为前缀 |
| 存在差异 | `false` | 双方均有取值但不等 |
| 无法比对（不确定） | `null` | 任一方缺失该项取值 |

**实现要点**：
- 双方均为空的层级直接跳过，不产生噪声行
- 名称项在任一侧缺失时同样判"无法比对（不确定）"，不做推定
- 输出压缩语句 `diff_summary_text()` 供 Excel「逐项差异说明」列使用，完整明细进入「逐项差异明细」工作表与 JSON `diff_rows`

## 五、统一社会信用代码校验（GB 32100-2015）

- 字符集（31 位）：`0123456789ABCDEFGHJKLMNPQRTUWXY`（不含 I、O、S、V、Z）
- 权重（前 17 位）：`1,3,9,27,19,26,16,17,20,29,25,13,8,24,10,30,28`
- 校验位：`C18 = 31 - (Σ Ci × Wi) mod 31`；若结果为 31 则取 0，再映射回字符集
- 常见错误：长度非 18 位、含非法字符、校验位不符

## 六、电话区号基准库（节选）

| 城市 | 区号 | 城市 | 区号 |
|---|---|---|---|
| 北京 | 010 | 长沙/株洲/湘潭 | 0731 |
| 上海 | 021 | 广州 | 020 |
| 天津 | 022 | 深圳 | 0755 |
| 重庆 | 023 | 武汉 | 027 |
| 成都 | 028 | 杭州 | 0571 |
| 南京 | 025 | 西安 | 029 |
| 郑州 | 0371 | 济南 | 0531 |
| 沈阳 | 024 | 哈尔滨 | 0451 |

**区号位数规则**：`010~029` 系列（直辖市及大区中心）为 **3 位**；其余为 **0xxx 共 4 位**。
该规则用于避免对无分隔符号码（如 `02038889999`）的贪婪误取。
完整库见 `scripts/normalizer.py` 的 `CITY_AREA_CODE`，可按项目所在地扩展。
