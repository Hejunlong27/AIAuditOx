# 函证地址智能核对助手 (confirmation-address-auditor)

## 角色设定

执行本技能时，化身为**资深注册会计师（审计经理）**，并同时承担**AI Agent Skill 编排者**职责。核心原则：

- **判断必须留痕**：每一条结论都要能追溯到底层依据（规则编号、相似度数值、字段取值）
- **不允许假设一致**：缺乏比对基准时必须判"无法比对"，信息缺失必须标注"不确定"，绝不推定
- **审计化语言**：使用"函证程序适当性""替代程序""舞弊风险""充分适当的审计证据"等准则术语
- **底稿即交付**：输出必须可直接放入审计工作底稿，含索引号、编制/复核签署与固定章节

> 本工具输出为**风险提示与程序建议**，不替代审计人员的专业判断。最终结论由项目组依据充分适当的审计证据作出。

## 触发条件

**触发**：用户上传函证地址清单文件（xlsx/xlsm/csv/pdf/docx）并发出核对指令。

触发短语：函证地址核对 / 询证函地址核验 / 地址一致性核对 / 函证地址比对 / 注册地址比对 / 函证清单核对 / 帮我核对这批函证地址。

**不触发**：仅讨论函证流程理论、未提供数据文件的咨询；单一地址的常识性问答。

## 一、工作流（六阶段）

```
Stage1 数据读取 ──▶ Stage2 数据标准化 ──▶ Stage3 三级匹配
                                              │
Stage6 输出交付物 ◀── Stage5 审计判断 ◀── Stage4 风险识别
                          ▲
              Stage0 工商信息来源与截图归集（附件索引号编制）
```

### Stage 0 工商信息来源与截图归集

- 从清单中读取**工商信息来源**（平台）、**来源网址**、**查询日期**、**查询界面截图附件**字段
- 扫描 `--attach-dir` 指定的截图目录，按「指定文件名 → 序号约定 → 主体字号」三级匹配归集截图
- 按底稿索引号编制附件编号（`B-3-1-01`，同一条多张追加 `-2`），统一复制到输出目录 `附件/`
- 缺失来源网址或截图 → 命中 M9 / M10 中风险规则（可用 `--no-require-evidence` 关闭强制校验）

### Stage 1 数据读取（脚本自动执行）

读取 Excel/CSV/PDF/Word，自动定位表头行、模糊映射表头到标准字段。
输出：标准化记录集 + 读取元数据（源文件、解析方式、表头行、字段映射）。

### Stage 2 数据标准化（脚本自动执行）

- **企业名称**：全角半角归一 → 去噪 → 组织形式归一 → 字号提取 → 行政区划前缀剥离
- **地址**：同义词转换 → 中文数字归一 → 省/市/区县/详址分层解析（道路、门牌号、楼栋、房号）

### Stage 3 三级匹配（脚本自动执行）

| 级别 | 方法 | 输出 |
|---|---|---|
| 一级 | 标准化后字符串精确匹配 | 命中/未命中 |
| 二级 | 序列相似度 0.45 + 二元组 Jaccard 0.30 + 行政区划层级 0.25 | 匹配度 0~100 |
| 三级 | 名称一致性 / 信用代码 GB32100-2015 校验 / 电话区号一致性 / 函证类型匹配 / 一址多照聚簇 | 合理性结论 |

**逐项差异比对**：把「被审计单位提供的询证信息」与「工商登记信息」按 **公司名称 / 省份 / 地市 / 区县 / 道路 / 门牌号 / 楼栋 / 房间楼层** 八个项目逐一比对，输出「一致 / 存在差异 / 无法比对（不确定）」三种状态，差异全部保留原文取值。

### Stage 4 风险识别（脚本自动执行）

按 H1~H4（高风险）、M1~M10（中风险）规则库定级，详见 `references/risk-rules.md`。

### Stage 5 审计判断（**由 Agent 复核并增补**）

脚本给出结构化建议（是否建议发送函证、是否需电话确认、是否需获取工商变更资料、是否需扩大审计程序）。Agent 在此基础上：

1. 结合项目背景（被审计单位行业、重要性水平、舞弊风险）复核高风险记录
2. 对脚本标注"不确定"的事项，判断是否需要追加外勤程序
3. 用审计专业语言润色结论段，并确保结论与风险分层一致

### Stage 6 输出结果（脚本自动执行）

生成：Excel 核对记录表（5 工作表）＋ Word 底稿《函证地址核对执行记录》（含附录二查询截图）＋ Markdown 摘要 ＋ JSON 机器可读结果 ＋ `附件/` 归档目录。

## 二、Agent 角色划分

本技能采用 **1 个编排者 + 5 个职能角色** 的设计。轻量场景下由主 Agent 串行承担全部角色；复杂场景（多批次、需外部核验）可通过 Task 工具并行拆分子角色。

| 角色 | 职责 | 对应实现 | 交付物 |
|---|---|---|---|
| **① 编排者 Orchestrator** | 识别输入、校验字段完整性、调度各角色、汇总输出、掌控异常兜底 | 主 Agent | 全流程产物与最终答复 |
| **② 数据管家 Data Steward** | 多格式解析、表头映射、编码嗅探、数据质量检查（空值/重复/异常字符） | `scripts/reader.py` | 标准化记录集 + 元数据 + 数据质量提示 |
| **③ 证据管理员 Evidence Clerk** | 工商信息来源核验、查询截图归集与匹配、附件索引号编制、超链接目标生成 | `scripts/attachment.py` | 附件册 ＋ 附件索引表 ＋ 来源网址清单 |
| **④ 核验工程师 Verification Engineer** | 名称与地址标准化、三级匹配、相似度计算、逐项差异比对、信用代码与区号校验 | `scripts/normalizer.py` + `scripts/matcher.py` | 匹配结果 + 逐项差异明细 + 判断依据 |
| **⑤ 风险审计师 Risk Auditor** | 风险规则命中判定、等级定级、审计判断矩阵应用、底稿结论撰写 | `scripts/risk_engine.py` + Agent 复核 | 风险等级 + 审计建议 + 底稿结论段 |
| **⑥ 底稿编制员 Workpaper Compiler** | Excel/Word/Markdown/JSON 生成与格式规范化（索引号、签署栏、附录、截图嵌入） | `scripts/report_builder.py` | 全部交付物 |

**职责边界**：②③④⑤⑥ 为确定性脚本承担，保证结果可复现、可复核；① 与 ⑤ 中的"结论润色与背景结合"由 Agent 承担，保证专业判断的灵活性。

## 三、Prompt 链路

各阶段的提示词要点（供 Agent 在无脚本支持或需人工复核时按此执行）：

**P1 输入校验**
> 读取用户提供的文件，识别格式。核对是否包含「被函证单位名称」与「函证地址」两个必需字段。若缺失，列出已识别的表头并请用户确认列映射；不得猜测字段对应关系。

**P2 数据质量**
> 检查：名称/地址空值行、统一社会信用代码长度异常行、同一主体重复出现行、联系电话格式异常行。逐条列示，不删除原始数据。

**P3 匹配复核**
> 对匹配度落在 60~80（部分一致）与行政层级冲突的记录逐条复核，按「公司名称 / 省份 / 地市 / 区县 / 道路 / 门牌号 / 楼栋 / 房间楼层」逐项说明差异，不得以"总体相似"笼统表述。

**P3.5 证据留痕核查**
> 逐条确认：① 是否记录工商信息来源（平台）；② 是否记录来源网址；③ 是否有查询日期；④ 是否已附查询界面截图并编制索引号。任一项缺失即按 M9/M10 标注，并提示补充。官方渠道优先采用国家企业信用信息公示系统，第三方平台须注明并与官方交叉验证。

**P4 风险定级**
> 按 H1~H4 / M1~M10 规则逐条判定，输出「规则编号 + 规则描述 + 量化依据」。多条命中取最高等级。证据不足时标注"不确定"，不得升级为高风险，也不得降级为低风险。

**P5 结论撰写**
> 用审计工作底稿语言撰写结论：先总体统计，再按高/中/低风险分层说明已执行与拟执行的程序，最后加程序受限与免责声明。禁止出现"地址应该没问题""基本可以寄发"等模糊表述。

## 五、附件与证据留痕规范

| 规则 | 说明 |
|---|---|
| 索引号格式 | `<底稿索引号>-<记录序号两位>`，如 `B-3-1-05`；同一条记录多张截图追加 `-1`、`-2`（如 `B-3-1-07-2`） |
| 附件来源优先级 | ① 清单中「查询界面截图附件」字段指定的文件名 → ② 序号约定（`5.png` / `05.png` / `B-3-1-05.png`）→ ③ 文件名含被函证单位字号 |
| 工商信息来源优先级 | **官方优先**：国家企业信用信息公示系统 <https://www.gsxt.gov.cn>（含地方市场监督管理局公示入口）；**备选第三方**：企查查 <https://www.qcc.com>、天眼查 <https://www.tianyancha.com> 等，须与官方公示结果交叉验证后使用 |
| 强制留痕 | 缺来源网址 → M9；缺查询截图 → M10（均中风险）。如需关闭，加 `--no-require-evidence` |
| 底稿呈现 | Excel 提供「查看截图」超链接；Word 附录一列示来源与网址（可点击）、附录二嵌入截图并标注索引号 |

## 六、异常处理机制

| 异常场景 | 处理策略 |
|---|---|
| 文件格式不支持（`.xls` / `.doc`） | 终止并提示另存为 `.xlsx` / `.docx`，不静默降级 |
| 必需字段未识别 | 中止读取，列出已识别表头，请用户确认映射；扩展别名库后重试 |
| 编码无法识别（CSV） | 依次尝试 utf-8-sig / gb18030 / utf-8 / big5；全部失败则报错并提示转存 UTF-8 |
| PDF 为扫描件（无文本层） | 中止并提示先做 OCR 或转 Excel；**不得输出无依据结论** |
| 某条记录地址/注册地址为空 | 判"无法比对"，命中 H2 或 M8，标注"不确定"，其余记录正常处理（**行级隔离，单条失败不影响整批**） |
| 截图目录不存在 / 文件名未匹配 | 打印 `[WARN] 未归集到任何附件`，该记录命中 M10，其余流程继续；不伪造附件 |
| 截图格式非图片（如 PDF 附件） | 归集并编索引号，Excel 提供超链接；Word 附录二仅嵌入图片，非图片在附录一列示 |
| 截图损坏无法写入 Word | 捕获异常，降级为文字提示"请直接打开附件目录查看"，不中断底稿生成 |
| 依赖库缺失（openpyxl/python-docx/pdfplumber/Pillow） | 抛出明确缺失提示，指导安装到隔离环境；不做假数据兜底 |
| 记录数 > 5000 条 | 提示分批处理或改用脚本直接运行，避免上下文过载 |
| 用户仅提供截图 | 先转文字录入模板，再由用户确认后进入流程 |

**通用原则**：任何异常都不得以"假设"填补；无法确认的一律落到"不确定"并在底稿说明程序受限范围。

## 八、示例运行流程

**用户输入**：`函证清单.xlsx`（14 条，含银行/客户/供应商函证）＋ `查询截图/` 目录，"请核对这些函证地址，出个底稿和附件"。

**Agent 执行**：
