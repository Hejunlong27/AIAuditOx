## 六要素（技能工厂确认记录）

| 要素 | 内容 |
|------|------|
| 审计目标 | 完整性（C）：所有应收利息均已记录（含未列示于账面者）；存在（E）：记录的应收利息于资产负债表日存在且归被审计单位拥有或控制；准确性（A）：金额正确计算、适当加总且准确记录；计价（V）：按恰当金额计价（含减值、摊销、公允价值等调整）；列报（P）：分类、披露恰当 |
| 所需资料 | 应收利息明细表（按金融资产/对手方）、债券与理财产品投资台账及合同、银行基准利率或协议利率文件、结息单与利息计算表、总账与明细账、银行收款流水与对账单、财务报表附注 |
| 所需数据 | 各金融资产本金或摊余成本、年利率、起息日与止息日、计息天数口径（actual/365 或 30/360）、期末余额、本期增减发生额、期后收款金额、外币折算汇率、实际执行的重要性水平 |
| 核对逻辑 | 1. 实质性分析程序（根据（如债券、理财产品）银行基准利率/与银行签订的协议,对计算利息收入的实际利率作出预期）；2. 应收利息明细表编制（获取或编制应收利息明细表）；3. 应收利息增减变动检查（检查应收利息增减变动）；4. 期后收款情况检查（检查期后收款情况）；5. 应收利息披露检查（审计应收利息的披露） |
| 底稿编制内容 | 见「产出清单」，全部底稿采用四段式制式：底稿名称与表头（项目基本信息）→ 审计目标和程序说明 → 审计程序执行结果 → 审计说明。共 5 张底稿。 |
| 输出格式 | xlsx 工作簿（模板见 templates/Z-7应收利息审计工作簿模板.xlsx），每份底稿同路径伴随「底稿名称+修订记录」.md |

## Steps（助理调度流程）

1. 确认项目工作目录已由项目经理指定（未指定则拒绝启动，升级项目经理）；在 `02_工作底稿/Z-7应收利息/` 下基于模板创建工作簿副本。
2. 校验输入资料完整性（见六要素「所需资料」）；缺失时向项目经理列明缺口清单并挂起。
3. 按依赖顺序分派实习生程序：P01 → P02 → P03 → P04 → P05；人工程序标记待办并跟踪完成状态。
4. 每个程序卡执行遵守「副本先行」：修改任何既有底稿前先创建副本入 `.auditox_backups/`；底稿每次生成/修订同步更新同路径「底稿名称+修订记录」.md。
5. 异常激活：按各程序卡「升级路径」处理，发现异常事项逐级升级。
6. 汇总各程序卡产出至工作簿，执行一级复核（见下方复核清单），复核通过后提交人工二级复核。

## 一级复核清单（助理执行，独立于编制上下文）

- 完整性：P01~P05 计划实施的程序均有底稿或「不适用+理由」记录；索引号连续无缺。
- 勾稽：明细表合计数 = 总账数 = 报表数；底稿间交叉索引正确。
- 证据充分性：每项结论可回溯到数据源；差异事项均有解释与支持文件。
- 异常闭环：所有异常事项有处理结果记录；未回函/回函差异已实施替代程序。
- 制式合规：每张底稿四段式结构完整，表头七要素齐全，修订记录同步。

## 边界与禁止事项

- 允许操作范围：仅项目工作目录内文件；仅调用 file_ops（读/写/改/格式）、数据核对脚本、Excel 计算。
- 禁止：物理删除任何文件（删除一律移入可恢复区）；向项目目录外发送客户数据；代替人工执行函证寄发/跟函/监盘动作；修改原始资料目录（01_原始资料 只读）；跳过强制程序。
- 数字核对一律使用脚本精确匹配，禁止以模型估算代替；差异原因说明可用模型起草，但必须标注「待人工确认」。

## Pitfalls

- 计息天数口径（actual/365、actual/360、30/360）与合同不一致会造成系统性利息偏差，须逐笔核对合同条款
- 一次性还本付息与分期付息债券的利息计提方式不同，勿套用同一模型
- 已到期未收回的利息应及时评估减值，勿与本金混淆列示
- 溢折价摊销（实际利率法）与票面利息的差额须区分列示，勿合并为一个「利息」
- 资产负债表日后至审计报告日之间的收款属期后事项，须纳入检查范围
- 外币债券利息应按资产负债表日汇率折算，勿沿用历史汇率

- 每张底稿「审计程序执行结果」与「审计说明」均有实质内容或明确的不适用声明。
- 修订记录 .md 与工作簿版本一一对应。
