# AuditOx 底稿制式规范（全局标准 · 写入所有角色）

> **【技能来源与使用声明】**
> **归属**：本技能属于「审小牛 AuditOx」开源审计技能组。
> **作者与许可**：何小疯27 · 免费开源 · 禁止商用转售
> **技能主页**：aiauditox.l.cd ｜ **开发动态**：公众号‘小小审计员日记’
> **使用声明**：本技能输出内容仅供学习与工作参考，不构成任何审计意见或专业建议；请勿将客户敏感数据用于公开的 AI 服务。

> 本规范为审小牛 AuditOx 所有审计程序技能的强制制式标准。任何角色（助理级/实习生级/技能工厂）编制工作底稿时**必须**遵循，确保同一套 agent 产出的底稿制式完全一致。

## 一、四段式制式结构（强制）

每张工作底稿（xlsx 工作簿中的每张表）必须严格按以下四段组织：

```
【底稿名称】（居中标题 + 索引号/来源/认定副标题）
一、项目基本信息
    被审计单位、审计期间、编制人、编制日期、审核人、审核日期、索引号
二、审计目标和程序说明
    审计目标一句话说明 + 程序表（序号/审计程序/对应认定/是否已实施[下拉:是/否/不适用]/执行结果说明）
三、审计程序执行结果
    数据表（含公式自动计算的列必须用公式，不得硬编码结果）；
    多个子程序时用 3.1/3.2/3.3 分区
四、审计说明
    编号说明行（1、2、…）+ 编制人/审核人签字行 + 修订记录伴随声明
```

制式细则：

1. 表头七要素（被审计单位、审计期间、编制人、编制日期、审核人、审核日期、索引号）缺一不可；
2. 索引号体系：`{组}-{报表项目序号}-{程序序号}`（资产类 Z / 负债类 F / 权益类 Q / 损益类 S / 通用辅助 A），如 Z-1-2-04；
3. 每份底稿（工作簿）同路径伴随「底稿名称+修订记录」.md，首次生成与每次修订同步登记；
4. 示例行用灰色斜体标注「（示例行，使用时删除）」；
5. 数字核对一律脚本精确匹配，禁止模型估算；金额格式 #,##0.00，百分比 0.00%。

## 二、三段式兜底底稿（程序信息不足时）

**触发条件**：技能工厂在 skill 化时，用户仅上传单个审计程序 Word 文档、或仅给出简单口头描述，不足以拆出可执行的多张专项程序底稿时。

**兜底产出**：生成三段式结构化底稿（工作簿含三张表，每张仍遵循四段式制式）：

| 表 | 内容 | 通用性依据 |
|----|------|-----------|
| 审定表 | 项目/子项目 × 期初期末（审前金额/审定金额）+ 调整数列 + 索引列；合计勾稽报表数、总账数 | 几乎所有报表项目均有审定表 |
| 明细表 | 子项目/明细维度的余额或发生额明细 + 合计 + 审计说明 | 几乎所有报表项目均有明细表 |
| 凭证抽查表 | 抽样记录（日期/凭证号/业务内容/会计分录/借方/贷方/核对要点√/是否异常/备注）+ 样本量与选样依据 + 审计结论 | 几乎所有报表项目均需凭证抽查 |

三张表索引号后缀：审定表 `-SA`、明细表 `-SB`、凭证抽查表 `-SC`（如 Z-5-1-SA）。

模板：`templates/通用三段式底稿模板.xlsx`。

## 三、技能工厂 skill 化流程（含兜底判定）

1. 用户上传完整程序库（多程序、含认定）→ 按程序拆分程序卡，产出专项底稿集（如 z-1-2 模式：封面+按程序底稿）；
2. 用户上传单个程序文档或简述 → 先按六要素对话引导补全（审计目标/所需资料/所需数据/核对逻辑/底稿内容/输出格式）；
3. 补全后仍不足以拆分专项程序 → 直接套用三段式兜底底稿（审定表/明细表/凭证抽查表），程序说明段照抄用户提供的程序描述，认定标注按用户描述或默认 CEAVP 全覆盖待确认；
4. 兜底底稿头部「二、审计目标和程序说明」中注明「本底稿采用通用三段式结构，程序依据为用户提供的程序描述，待专家确认后可升级为专项底稿」。

## 四、其他强制项（沿承主方案）

- 工作目录门禁：项目未指定工作目录拒绝启动；
- 副本先行：修改任何既有底稿前先创建 .bak 入 .auditox_backups/；
- 禁止物理删除：删除一律移入可恢复区；
- 动作边界：仅项目工作目录内操作，禁止外发客户数据。

## 五、输出形态与 Excel 制式（xlsx 优先 · 制式统一）

- 正式工作底稿输出 **Excel(.xlsx)**（日常审计惯例），同路径伴生 `.md` 预览/修订；不得以纯 md 冒充正式底稿交付。
- **统一规约源**：底稿内容（表头七要素 + 一/二/三/四段）先表达为**底稿规约 JSON**（由 workpaper 填充/导出工具产出），`.md` 渲染与 `.xlsx` 导出共用同一规约 → 制式天然统一、改一处全同步。
- xlsx 布局要点（与技能包 templates/ 模板一致）：工作表名=底稿索引号；顶部标题区（底稿名称+索引）；表头七要素区；一、二、三、四段各占区；金额列格式 `#,##0.00`、百分比 `0.00%`；合计/汇总行加粗；示例行删除。
- 转换工具：`xlsx_export`/`workpaper_to_excel`（@auditox/dsh-tools，exceljs 实现；Python 备选 openpyxl sidecar）——把规约 JSON 转成 .xlsx；无该能力时先出 .md 并注明「待转 xlsx」。

## 六、资料索取先行（全局强制流程）

- 任一程序卡启动前：先输出「所需资料/数据清单」（源自六要素「所需资料/所需数据」），缺口逐项向用户索取；未齐备不得执行数字核对，须挂起。
- 人工主导程序（函证/监盘等）用户未提供载体时，登记「待人工/排期」挂起，不硬跑。
- 底稿「数据源」须注明实际使用的资料文件，保证可追溯（V7）。

## Verification

- 检查任一 AuditOx 产出的底稿：四段结构完整、七要素齐全、索引号合规、修订记录同步；
- 兜底场景：确认三张表（SA/SB/SC）齐全且程序说明段有「待专家确认」标注。
