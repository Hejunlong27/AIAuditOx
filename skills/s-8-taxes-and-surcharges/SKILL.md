## 六要素（技能工厂确认记录）

| 要素 | 内容 |
|------|------|
| 审计目标 | 完整性（C）：所有税金及附加均已记录（含未列示于账面者）；存在（E）：记录的税金及附加于资产负债表日存在且归被审计单位拥有或控制；准确性（A）：金额正确计算、适当加总且准确记录；计价（V）：按恰当金额计价（含减值、摊销、公允价值等调整）；列报（P）：分类、披露恰当 |
| 所需资料 | 税金及附加明细表（按税种）、总账与明细账、各税种纳税申报表与完税凭证、应税收入或应税数量基础数据、增值税与消费税申报数、税收政策文件与税率依据、税收优惠批准文件、税务机关检查结论、报表附注 |
| 所需数据 | 各税种计税依据（审定数）、适用税率或征收率、本期计提额与缴纳额、期末应交余额、本期应纳增值税与消费税合计数、税收优惠金额、税务检查涉及的额外付款与罚金、实际执行的重要性水平 |
| 核对逻辑 | 1. 税金及附加明细表编制与核对（获取税金及附加明细表）；2. 各税种计算与勾稽复核（复核税种核算是否符合税收政策）；3. 税务合规、争议与特殊税收项目检查（复核是否遵守税务机关的规定）；4. 税金及附加披露检查（审计税金及附加披露） |
| 底稿编制内容 | 见「产出清单」，全部底稿采用四段式制式：底稿名称与表头（项目基本信息）→ 审计目标和程序说明 → 审计程序执行结果 → 审计说明。共 4 张底稿。 |
| 输出格式 | xlsx 工作簿（模板见 templates/S-8税金及附加审计工作簿模板.xlsx），每份底稿同路径伴随「底稿名称+修订记录」.md |

## Steps（助理调度流程）

1. 确认项目工作目录已由项目经理指定（未指定则拒绝启动，升级项目经理）；在 `02_工作底稿/S-8税金及附加/` 下基于模板创建工作簿副本。
2. 校验输入资料完整性（见六要素「所需资料」）；缺失时向项目经理列明缺口清单并挂起。
3. 按依赖顺序分派实习生程序：P01 → P02 → P03 → P04；人工程序标记待办并跟踪完成状态。
4. 每个程序卡执行遵守「副本先行」：修改任何既有底稿前先创建副本入 `.auditox_backups/`；底稿每次生成/修订同步更新同路径「底稿名称+修订记录」.md。
5. 异常激活：按各程序卡「升级路径」处理，发现异常事项逐级升级。
6. 汇总各程序卡产出至工作簿，执行一级复核（见下方复核清单），复核通过后提交人工二级复核。

## 一级复核清单（助理执行，独立于编制上下文）

- 完整性：P01~P04 计划实施的程序均有底稿或「不适用+理由」记录；索引号连续无缺。
- 勾稽：明细表合计数 = 总账数 = 报表数；底稿间交叉索引正确。
- 证据充分性：每项结论可回溯到数据源；差异事项均有解释与支持文件。
- 异常闭环：所有异常事项有处理结果记录；未回函/回函差异已实施替代程序。
- 制式合规：每张底稿四段式结构完整，表头七要素齐全，修订记录同步。

## 边界与禁止事项

- 允许操作范围：仅项目工作目录内文件；仅调用 file_ops（读/写/改/格式）、数据核对脚本、Excel 计算。
- 禁止：物理删除任何文件（删除一律移入可恢复区）；向项目目录外发送客户数据；代替人工执行函证寄发/跟函/监盘动作；修改原始资料目录（01_原始资料 只读）；跳过强制程序。
- 数字核对一律使用脚本精确匹配，禁止以模型估算代替；差异原因说明可用模型起草，但必须标注「待人工确认」。

## Pitfalls

- 城建税、教育费附加的计税依据应与本期实际应纳增值税与消费税合计数一致，勿直接套用账面已缴流转税（存在预缴或缓缴时必然不符）
- 印花税、房产税、土地使用税、车船税按期申报而非按月计提，期末易漏提，须核对全年度申报表与账面计提数
- 税金及附加不含增值税与企业所得税（后者计入所得税费用），勿混入
- 税收优惠与减免须取得批准文件；仅有管理层口头说明的减免不得作为依据
- 税务机关检查形成的罚金与滞纳金应计入营业外支出，不计入税金及附加
- 税率变更期间须按纳税义务发生时间分段计算，勿整期套用新税率
