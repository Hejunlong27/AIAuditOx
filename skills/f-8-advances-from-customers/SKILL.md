## 六要素（技能工厂确认记录）

| 要素 | 内容 |
|------|------|
| 审计目标 | 完整性（C）：所有预收账款均已记录（含未列示于账面者）；存在（E）：记录的预收账款于资产负债表日存在且归被审计单位拥有或控制；准确性（A）：金额正确计算、适当加总且准确记录；计价（V）：按恰当金额计价（含减值、摊销、公允价值等调整）；列报（P）：分类、披露恰当 |
| 所需资料 | 预收账款明细表（按客户）、总账与明细账、销售合同与订单（含预收条款）、仓库发货记录与货运单据、收款凭证、至审计时已转销款项清单、客户名称与地址清单、函证控制表与回函、应收账款明细（两方挂账检查用）、报表附注 |
| 所需数据 | 各客户期初与期末余额、本期增减发生额、借方余额项目、已转销金额与转销日期、发货日期、合同金额与预收比例、函证金额与回函金额、实际执行的重要性水平 |
| 核对逻辑 | 1. 预收账款明细表编制与核对（获取或编制预收账款明细表）；2. 转销与期后检查（抽查预收账款有关的销货合同、仓库发货记录、货运单据和收款凭证，检查已实现销售的商品是否及时转销预收账款，确定预收账款期末余额的正确性和合理性。）；3. 预收账款函证程序（实施函证程序）；4. 预收账款披露检查（审计预收账款的披露） |
| 底稿编制内容 | 见「产出清单」，全部底稿采用四段式制式：底稿名称与表头（项目基本信息）→ 审计目标和程序说明 → 审计程序执行结果 → 审计说明。共 4 张底稿。 |
| 输出格式 | xlsx 工作簿（模板见 templates/F-8预收账款审计工作簿模板.xlsx），每份底稿同路径伴随「底稿名称+修订记录」.md |

## Steps（助理调度流程）

1. 确认项目工作目录已由项目经理指定（未指定则拒绝启动，升级项目经理）；在 `02_工作底稿/F-8预收账款/` 下基于模板创建工作簿副本。
2. 校验输入资料完整性（见六要素「所需资料」）；缺失时向项目经理列明缺口清单并挂起。
3. 按依赖顺序分派实习生程序：P01 → P02 → P03 → P04；人工程序标记待办并跟踪完成状态。
4. 每个程序卡执行遵守「副本先行」：修改任何既有底稿前先创建副本入 `.auditox_backups/`；底稿每次生成/修订同步更新同路径「底稿名称+修订记录」.md。
5. 异常激活：按各程序卡「升级路径」处理，发现异常事项逐级升级。
6. 汇总各程序卡产出至工作簿，执行一级复核（见下方复核清单），复核通过后提交人工二级复核。

## 一级复核清单（助理执行，独立于编制上下文）

- 完整性：P01~P04 计划实施的程序均有底稿或「不适用+理由」记录；索引号连续无缺。
- 勾稽：明细表合计数 = 总账数 = 报表数；底稿间交叉索引正确。
- 证据充分性：每项结论可回溯到数据源；差异事项均有解释与支持文件。
- 异常闭环：所有异常事项有处理结果记录；未回函/回函差异已实施替代程序。
- 制式合规：每张底稿四段式结构完整，表头七要素齐全，修订记录同步。

## 边界与禁止事项

- 允许操作范围：仅项目工作目录内文件；仅调用 file_ops（读/写/改/格式）、数据核对脚本、Excel 计算。
- 禁止：物理删除任何文件（删除一律移入可恢复区）；向项目目录外发送客户数据；代替人工执行函证寄发/跟函/监盘动作；修改原始资料目录（01_原始资料 只读）；跳过强制程序。
- 数字核对一律使用脚本精确匹配，禁止以模型估算代替；差异原因说明可用模型起草，但必须标注「待人工确认」。

## Pitfalls

- 同一客户同时挂应收与预收（两方挂账）会同时虚增资产与负债，须结合应收账款明细逐户检查并评估是否需抵销列报
- 借方余额本质是已转销或多转销，须查明并评估重分类为应收账款
- 转销日期早于发货日期是提前确认收入的典型信号，须逐笔核对发货记录与转销凭证
- 长期挂账未转销的预收账款可能是收入未及时确认，也可能是存在退款义务，两种处理方向相反，须取得管理层说明与支持证据
- 预收账款与合同负债的划分应按准则判断（是否对应可明确区分的履约义务），勿一概计入预收账款
- 函证回函率低时不能只以替代程序了结，须评估是否存在管理层不配合的迹象
