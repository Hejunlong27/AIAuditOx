# 01 · 文档分类与版式判别

> 本文件定义「原始文件 → 文档类型」的判别规则。类型判定决定后续走哪套字段抽取规则，判错会导致抽取全盘失效，因此采用**多信号加权 + 低置信度降级为通用 OCR** 的策略。

## 一、支持的文档类型

| type 标识 | 中文名 | 典型来源 | 抽取目标 |
|---|---|---|---|
| `vat_invoice` | 增值税发票（专票/普票/电子发票/全电发票） | 扫描件、PDF、OFD 转图 | 号码、日期、购销方、金额、税额、价税合计 |
| `receipt` | 通用票据（收据、银行回单、支票、汇票、完税凭证） | 扫描件、手机拍照 | 出票/收款方、金额、日期、账号、用途 |
| `contract` | 合同/协议 | PDF、扫描件 | 当事人、标的、金额、期限、付款条件、违约条款、签署信息 |
| `statement` | 对账单/明细表 | PDF、Excel 打印件 | 表头、行项目、合计 |
| `generic` | 通用文档（无法归入以上） | 任意 | 全文 Markdown |

**判别优先级**：先判定是否为 `vat_invoice`（特征最强），再 `receipt`，再 `contract`，兜底 `generic`。

## 二、判别信号

### 2.1 关键词信号（OCR 全文命中）

| 类型 | 强特征词（命中 ≥2 个视为强信号） | 弱特征词 |
|---|---|---|
| `vat_invoice` | `增值税专用发票` `增值税普通发票` `电子发票` `发票号码` `价税合计` `税率` `税额` `销售方` `购买方` `开票日期` | `统一社会信用代码` `开户行` `校验码` |
| `receipt` | `收据` `银行回单` `进账单` `付款凭证` `完税证明` `税收缴款书` `支票` `汇票` `收款人` | `金额大写` `用途` `交易流水` |
| `contract` | `合同` `协议` `甲方` `乙方` `签订地点` `签订日期` `第一条` `违约责任` `争议解决` `本合同` | `盖章` `法定代表人` `委托代理人` |
| `statement` | `对账单` `明细表` `余额` `本期发生额` `累计` | `序号` `合计` |

### 2.2 版式信号

| 类型 | 版式特征 |
|---|---|
| `vat_invoice` | 有框线表格、顶部有「发票」字样与发票监制章区域、右上角号码区、底部有开票人/复核人/收款人三栏 |
| `receipt` | 窄长版式或明显银行模板抬头、有「金额（大写）」栏 |
| `contract` | 段落式文本、标题居中、末尾有签章区、常见页码「第 X 页 共 Y 页」 |

### 2.3 判定算法

```
score[type] = 2.0 × 强特征命中数 + 1.0 × 弱特征命中数 + 1.5 × 版式信号命中
若 max(score) >= 3.0 且 max/次大 >= 1.5  → 采纳该类型
若 max(score) >= 3.0 但两类接近        → 采纳 max，标记 ambiguous=true
否则                                    → generic
```

**多页文档**：逐页判定，取众数作为文档类型；若各页类型不一致（如「合同 + 发票附件」），按页分别抽取，文档级 type 记为 `mixed`。

## 三、置信度与降级

- 分类置信度 < 0.6 → `type_confidence: low`，仍执行抽取但全部字段标 `needs_review`。
- 判为 `generic` 时不执行字段抽取，只输出 Markdown 全文。
- **绝不因分类不确定而拒绝输出** —— 审计场景下「给出全文 + 标注不确定」优于「报错退出」。

## 四、常见误判与规避

| 误判 | 成因 | 规避 |
|---|---|---|
| 合同附件发票被判为 `contract` | 合同正文含「发票」字样 | 强特征词要求 ≥2 且必须含 `发票号码` 或 `价税合计` |
| 银行回单被判为 `vat_invoice` | 都含「金额」「日期」 | 回单不含 `税额`/`税率`/`价税合计` 三件套 |
| 电子发票 PDF 被判 `generic` | PDF 为纯文本层，OCR 输出无框线 | 优先读 PDF 文本层，文本层命中关键词同样计入 |
