# 04 · 准确性校验与人工复核

> **本 skill 的第一原则：宁可标"不确定"，不可给"看起来对"的错值。**
> 审计场景下，一个被静默修正的错误金额，比一个明确标注「需人工核对」的字段危险得多。

## 一、四层校验

| 层级 | 校验内容 | 失败后果 |
|---|---|---|
| L1 字符级 | OCR 置信度阈值 | 低于阈值 → 字段标 `low_confidence` |
| L2 格式级 | 正则、长度、校验位、日期合法性 | 失败 → 字段标 `format_invalid` |
| L3 逻辑级 | 金额勾稽、大小写一致、明细合计、同名检测 | 失败 → 文档标 `needs_review` |
| L4 跨文档级 | 同批次内发票号重复、购销方名称不一致、金额与银行流水不匹配 | 失败 → 写入 `_index.json` 的 `anomalies` |

## 二、置信度阈值

| 场景 | 阈值 | 说明 |
|---|---|---|
| 关键字段（号码、日期、三金额） | 0.90 | 低于此值必须人工核对 |
| 一般字段（名称、税号、备注） | 0.80 | |
| 全文 Markdown | 0.60 | 低于此值该行标 `[?]` 前缀 |

字段置信度 = 该字段所有来源文本行的**最低** score（取最弱环节，不取平均）。

## 三、校验项明细

### 3.1 发票

| 校验项 | 规则 | 标记 |
|---|---|---|
| 金额勾稽 | `amount_ex_tax + tax_amount ≈ total_amount`（容差 0.01） | `arithmetic_ok` |
| 大小写一致 | 大写金额转数字 = 小写 | `case_mismatch` |
| 明细合计 | Σitems.amount ≈ amount_ex_tax | `items_sum_mismatch` |
| 税率合法 | ∈ {0, 1%, 3%, 5%, 6%, 9%, 13%} 或特殊征收率 | `tax_rate_invalid` |
| 税号校验位 | 18 位 GB32100 校验 | `checksum_failed` |
| 购销方同名 | buyer_name ≠ seller_name | `same_party` |
| 号码长度 | ∈ {8, 20} | `invoice_no_invalid` |
| 日期区间 | 年份 ∈ [2015, 当前年+1] | `date_out_of_range` |

### 3.2 合同

| 校验项 | 规则 | 标记 |
|---|---|---|
| 条款切分有效性 | 条款数 ≥ 3 或全文 < 2000 字 | `clause_split` |
| 金额一致性 | 多处金额互相矛盾 | `amount_candidates` |
| 签章存在 | 版面检出 seal 类区域 | `seal_missing` |
| 甲乙方完整 | parties 至少 2 方且名称非空 | `parties_incomplete` |
| 日期合法 | 签订日期合法且不晚于当前日期+1年 | `date_invalid` |

### 3.3 跨文档

| 校验项 | 规则 | 标记 |
|---|---|---|
| 发票号重复 | 同批次 invoice_no 重复 | `duplicate_invoice` |
| 购销方名称漂移 | 同一税号对应多个名称 | `name_drift` |
| 金额异常集中 | 同批次出现大量相同金额（如 9999.00） | `amount_cluster` |

## 四、复核清单（输出到 `_review.md`）

每次运行生成一份人工复核清单，按优先级排序：

```
P0（必须核对，否则不可用）
  - 勾稽失败：发票号 XXXXXXXX，差额 0.02
  - 必填字段缺失：发票号 XXXXXXXX，缺开票日期
P1（建议核对）
  - 低置信度：发票号 XXXXXXXX，税额 score=0.83
  - 税号校验位失败：销售方 XXXX
P2（提示）
  - 购销方同名：XXXX
  - 同批次发票号重复
```

## 五、字段溯源

每个抽取字段必须带 `evidence`：

```json
{
  "value": "12345.67",
  "confidence": 0.96,
  "evidence": {
    "page": 1,
    "bbox": [820, 640, 1180, 690],
    "raw_text": "价税合计（小写） ¥12345.67",
    "source": "label_adjacent"
  }
}
```

`source` 取值：`label_adjacent` / `regex` / `table_cell` / `region`。
**无 evidence 的字段一律视为不可信**，运行时会校验这一点。

## 六、性能与准确性的权衡

| 策略 | 耗时影响 | 准确性影响 | 采用 |
|---|---|---|---|
| 全页跑 PP-StructureV3 版面分析 | 高（~1.5s/页 GPU） | 表格还原准 | 合同、对账单采用 |
| 仅跑 OCR 检测+识别 | 低（~0.3s/页 GPU） | 无版面结构 | 发票、票据采用（版式固定） |
| 图片超分预处理 | +0.5s/页 | 低分辨率扫描件显著提升 | 仅当页宽 < 1200px 时启用 |
| 多尺度重复识别投票 | ×3 耗时 | 小幅提升 | **不采用**（性价比低） |
| 关键字段二次识别 | +0.1s/字段 | 高（针对低分区） | 采用：score < 0.85 时对该区域放大重识别 |

**结论**：耗时优化靠「按文档类型选模型」，不靠「牺牲识别精度」。低置信度区域**二次识别**是唯一值得的额外开销。

## 七、缓存与增量

- 页图 SHA256 → 识别结果缓存（`.ocr-cache/`），命中直接复用，重复跑同批文件耗时趋近 0。
- 输出目录已存在同名 JSON 且源文件 mtime 未变 → 跳过。
- 批量处理时每完成一个文件即落盘，中断不丢已完成结果。
