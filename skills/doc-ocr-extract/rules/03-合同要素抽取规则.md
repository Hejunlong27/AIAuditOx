# 03 · 合同要素抽取规则

> 合同是长文本、非固定版式，**不适合纯正则抽取**。本 skill 的策略是：
> **确定性地把合同切成「条款块 + 关键段落」，输出带页码/锚点的结构化骨架；语义判断交给上层审计技能（LLM）。**
> 理由：审计底稿要求可追溯，机器强行"理解"合同条款易产生幻觉；把切分做准、把原文摆好，才是可靠的分工。

## 一、抽取产出

| 产出 | 内容 | 消费者 |
|---|---|---|
| `meta` | 合同名称、编号、签订日期、签订地点、页数 | 底稿封面 |
| `parties` | 甲方/乙方/丙方的名称、住所、法定代表人、联系人 | 关联方核查、函证 |
| `clauses` | 条款树（条号 + 标题 + 正文 + 页码 + 原文锚点） | 条款审查、CAS14 五步法 |
| `key_terms` | 金额、期限、付款方式、税率、保证金、违约金比例 | 实质性分析、截止测试 |
| `signatures` | 签署方、签署日期、盖章位置（页/坐标） | 完整性核查 |
| `full_text` | 全文 Markdown（含页码标记） | 全文检索、LLM 精读 |

## 二、条款切分算法

### 2.1 条号识别

支持的中文合同条号格式（按优先级）：

```
第X条              → 第[一二三四五六七八九十百零〇\d]+条
X、  / X.  / X．    → 顶层序号（行首）
（X）/(X)           → 二级序号
X.X / X.X.X        → 数字层级
```

切分规则：
1. 按行扫描，命中条号正则且该行长度 < 60 字（防正文中的"第3条约定"误切）→ 视为条款起点。
2. 条款标题取条号后同行文本（去除标点），若同行无内容则取下一行前 40 字。
3. 条款正文 = 起点行到下一条款起点前的全部文本。
4. 条款层级：`第X条` 为一级，其下 `（X）` 为二级，`X.X` 按点数定级。

### 2.2 章节识别（可选）

若合同含「第一章 总则」式章节，先按章切，再章内切条，形成两级树。

### 2.3 跨页合并

条款跨页时，页眉页脚（页码行、公司名行、密级行）需剔除后再合并：
- 剔除规则：整行匹配 `^第?\s*\d+\s*页`、`共\s*\d+\s*页`、`^-\s*\d+\s*-$`、页眉重复行（同位置多页重复出现的短行）。

## 三、关键要素抽取

### 3.1 合同金额

- 优先匹配含「合同总价」「合同金额」「价款」「总金额」「人民币」的段落。
- 金额正则：`[¥￥]?\s*([0-9][0-9,]*\.?\d{0,2})\s*(元|万元|亿元)`
- 单位归一：`万元` ×10000，`亿元` ×100000000。
- 大写金额同步抽取，交叉校验。
- **多金额情形**：含「暂定」「预估」「据实结算」「以实际发生为准」→ 标 `is_estimate: true`，此字段不可直接用于实质性分析。

### 3.2 履行期限

- 匹配模式：`自\s*(.{4,20})\s*起\s*至\s*(.{4,20})\s*止`、`合同有效期`、`服务期限`、`工期`、`履行期限`
- 输出 `{start, end, raw}`，日期归一化失败则保留原文。

### 3.3 付款条件

- 匹配含「付款」「结算」「支付」的条款，抽取：付款比例（`\d+(\.\d+)?%`）、付款节点（预付款/进度款/验收款/质保金）、账期（`\d+\s*(天|日|个月)`）。
- 预付款比例是审计重点（收入确认时点、资金占用）。

### 3.4 违约与争议

- 违约金比例：`违约金.*?(\d+(\.\d+)?)\s*%`、`每日\s*(\d+(\.\d+)?)\s*[%‰]`
- 争议解决方式：仲裁 / 诉讼，及管辖地。

### 3.5 签署信息

- 签署方：末尾「甲方（盖章）」「乙方（盖章）」区块内的名称。
- 签署日期：签章区日期 > 正文「签订日期」。
- **缺章检测**：若签章区附近 OCR 未检出印章类图形（PP-StructureV3 版面 `seal` 类）→ 标 `seal_missing`，这是审计关注点。

## 四、准确性约束

1. **条款切分只做结构，不做语义归纳** —— 不得输出「本合同为固定总价合同」这类判断，除非原文明确出现该表述。
2. **每个 clause 必须带 `page` 和 `bbox`**，便于人工回原页核对。
3. **切分失败降级**：若识别出的条款数 < 3 且全文 > 2000 字 → 判为「切分失败」，改输出「段落块 + 页码」的粗粒度结构，并标 `clause_split: failed`。
4. **金额要素冲突**：合同多处出现不同金额（如总价 vs 分期明细合计）→ 全部保留，标 `amount_candidates`，不择一。
