# 02 · 发票字段抽取规则

> 适用范围：增值税专用发票、增值税普通发票、电子发票（PDF/OFD 转图）、全电发票（数电票）。
> 原则：**只抽 OCR 文本里真实出现的值，不做推断、不做补全**。抽不到写 `null` 并标记原因。

## 一、字段清单

| 字段 key | 中文名 | 必填 | 格式 | 说明 |
|---|---|---|---|---|
| `invoice_code` | 发票代码 | 否 | 10/12 位数字 | 全电发票无此字段 |
| `invoice_no` | 发票号码 | **是** | 8 位（传统）/ 20 位（全电） | 核心唯一标识 |
| `invoice_date` | 开票日期 | **是** | YYYY-MM-DD | 原文常见「2026年10月28日」 |
| `invoice_type` | 票种 | 否 | 枚举 | 专票/普票/电子普票/全电专票/全电普票 |
| `buyer_name` | 购买方名称 | **是** | 文本 | |
| `buyer_tax_id` | 购买方纳税人识别号 | 否 | 15/18/20 位 | 18 位需过校验位 |
| `seller_name` | 销售方名称 | **是** | 文本 | |
| `seller_tax_id` | 销售方纳税人识别号 | 否 | 15/18/20 位 | |
| `amount_ex_tax` | 金额（不含税） | **是** | 数值(2位小数) | |
| `tax_amount` | 税额 | **是** | 数值(2位小数) | |
| `total_amount` | 价税合计（小写） | **是** | 数值(2位小数) | |
| `total_amount_cn` | 价税合计（大写） | 否 | 文本 | 用于交叉校验 |
| `tax_rate` | 税率 | 否 | 百分比 | 可能多行（不同商品不同税率） |
| `items` | 货物或应税劳务明细 | 否 | 列表 | 名称/规格/数量/单价/金额/税率/税额 |
| `remark` | 备注 | 否 | 文本 | 常见「合同号 XXX」——审计关联线索 |
| `payee` | 收款人 | 否 | 文本 | |
| `reviewer` | 复核人 | 否 | 文本 | |
| `drawer` | 开票人 | 否 | 文本 | |

## 二、定位策略（按优先级）

1. **标签邻近法**：OCR 文本行含标签词（如 `发票号码`），取同一行标签右侧文本，或下一行最近文本。
2. **区域法**：按版面分析结果，发票通常有固定区域（右上角号码区、左上购买方区、左下销售方区）。
3. **正则直捕**：对高辨识度格式直接全页正则扫描。

三种策略结果不一致时 → 记 `conflict`，取正则结果并标记 `needs_review`。

## 三、各字段抽取细则

### 3.1 发票号码 `invoice_no`

- 正则：`(?:发票号码|No[.:]?)\s*[:：]?\s*(\d{8}|\d{20})`
- 全电发票 20 位，传统 8 位。若捕获到 20 位但文本含「发票代码」→ 实为代码，回退。
- 校验：纯数字、长度 ∈ {8, 20}。

### 3.2 开票日期 `invoice_date`

- 正则：`(\d{4})\s*[年\-/.]\s*(\d{1,2})\s*[月\-/.]\s*(\d{1,2})`
- 归一化为 `YYYY-MM-DD`。
- 合理性：年份 ∈ [2015, 当前年+1]，月份 1-12，日 1-31 且为合法日期。

### 3.3 纳税人识别号 `*_tax_id`

- 正则：`([0-9A-Z]{15,20})`
- **18 位统一社会信用代码校验位算法**（GB 32100-2015）：
  - 字符集：`0123456789ABCDEFGHJKLMNPQRTUWXY`（无 I、O、S、V、Z）
  - 权重：`[1,3,9,27,19,26,16,17,20,29,25,13,8,24,10,30,28]`
  - `校验位 = 31 - (Σ(ci × wi) mod 31)`，结果 31 时取 0
  - 校验失败 → 该字段标 `checksum_failed`，**仍保留原值**（OCR 可能识别错，需人工核对）

### 3.4 金额三件套

| 字段 | 抽取方式 |
|---|---|
| `amount_ex_tax` | 标签「金额」右侧数字，或明细行「金额」列合计 |
| `tax_amount` | 标签「税额」右侧数字 |
| `total_amount` | 标签「价税合计（小写）」右侧带 `¥`/`￥` 的数字 |

- 数值正则：`[¥￥]?\s*([0-9,]+\.\d{2})`，去千分位。
- **勾稽校验**：`|amount_ex_tax + tax_amount - total_amount| <= 0.01`
  - 通过 → `arithmetic_ok: true`
  - 失败 → `arithmetic_ok: false` + `needs_review`，并在报告里列出三者差值
- **大小写交叉校验**：`total_amount_cn` 转数字后与 `total_amount` 比对，不一致 → `case_mismatch`。

### 3.5 金额大写转数字

支持：`壹贰叁肆伍陆柒捌玖零` / `拾佰仟万亿` / `元角分整`。
- 例：`壹万贰仟叁佰肆拾伍元陆角柒分` → `12345.67`
- 例：`伍佰元整` → `500.00`
- 转换失败 → 不参与校验，记 `cn_parse_failed`。

### 3.6 购销方名称

- 购买方区域：标签「购买方」/「购方」下方或右侧的名称行。
- 销售方区域：标签「销售方」/「销方」下方或右侧的名称行。
- 名称清洗：去除首尾空白、去除 `名称：` 前缀、去除误识别的框线字符。
- **同名检测**：购买方 = 销售方 → 异常，标记 `same_party`（关联交易或识别错误）。

### 3.7 明细行 `items`

表头识别关键词：`货物或应税劳务、服务名称` / `规格型号` / `单位` / `数量` / `单价` / `金额` / `税率` / `税额`。
- 表格结构优先用 PP-StructureV3 的表格识别结果；无表格结果时按文本行 + 坐标聚列。
- 明细合计与 `amount_ex_tax` 比对，差 > 0.01 → `items_sum_mismatch`。

## 四、质量分级

| 等级 | 条件 | 处理 |
|---|---|---|
| A | 号码+日期+购销方+三金额齐全，勾稽通过，全部字段 score ≥ 0.90 | 直接可用 |
| B | 齐全且勾稽通过，但有字段 score ∈ [0.75, 0.90) | 输出 + 提示核对低分字段 |
| C | 勾稽失败，或必填字段缺失，或存在 conflict | 输出 + `needs_review: true` + 列明原因 |
| D | 号码与日期都抽不到 | 仅输出 Markdown，不进结构化表 |

## 五、禁止事项

1. 不得用「同类发票的常见值」填充缺失字段。
2. 不得因勾稽失败而修改任一金额字段去凑平 —— 只报告，不修正。
3. 不得跨发票复用购销方信息。
