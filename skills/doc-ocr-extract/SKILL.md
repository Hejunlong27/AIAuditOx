# 文档识别与结构化（基础技能）

> **【技能来源与使用声明】**
> **归属**：本技能属于「审小牛 AuditOx」开源审计技能组。
> **作者与许可**：何小疯27 · 免费开源 · 禁止商用转售
> **技能主页**：aiauditox.l.cd ｜ **开发动态**：公众号‘小小审计员日记’
> **使用声明**：本技能输出内容仅供学习与工作参考，不构成任何审计意见或专业建议；请勿将客户敏感数据用于公开的 AI 服务。

> 技能库分组：辅助分析类 → 基础支撑（工具型单体技能，无子技能）
> 定位：**所有审小牛技能的上游输入层**。审计程序拿到的往往是 PDF 扫描件、手机拍的发票、一沓合同，本技能负责把它们变成「可读、可检索、可校验、可溯源」的结构化数据。
> 核心约束：**全流程本地推理，不调用任何云端 OCR 或大模型服务** —— 客户合同与发票属于高度敏感资料。

## 为什么不用大模型 OCR

| 方案 | 8GB 显存可行性 | 隐私 | 结论 |
|---|---|---|---|
| Unlimited-OCR-2（6.69GB 权重） | 加载后仅剩 ~1GB 给激活，频繁 OOM / 回退 CPU | 本地 | 显存不足，不适合本机 |
| 云端 OCR API | 可行 | **客户资料出本机，审计场景不可接受** | 排除 |
| **PaddleOCR PP-OCRv6 + 规则抽取** | 模型 ~140MB，显存占用 <2GB | 本地 | **采用** |

本技能选择「**轻量高精度 OCR + 确定性规则抽取 + 强校验**」而非「大模型端到端识别」，原因：
1. 发票是**固定版式**，规则抽取比模型更稳、可解释、可审计；
2. 审计底稿要求**每个数字都能回原页核对**，模型输出无法提供坐标溯源；
3. 确定性规则**不会幻觉** —— 抽不到就是空，不会编一个"看起来合理"的金额。

## 六要素

| 要素 | 内容 |
|------|------|
| 解决什么 | 原始文件（PDF/图片）→ 可复用文档（Markdown + 结构化 JSON），支撑下游审计程序 |
| 输入 | 单个文件或目录；PDF（电子/扫描）、JPG/PNG/BMP/TIFF/WEBP |
| 输出 | `<名>.md` 版面还原全文、`<名>.json` 结构化字段（带页码/坐标/原文）、`<名>.lines.json` 原始文本行、`_index.json` 批次索引、`_review.md` 人工复核清单 |
| 支持的文档类型 | 增值税发票（专票/普票/电子/全电）、票据（收据/银行回单/完税凭证）、合同/协议、对账单、通用文档 |
| 运行环境 | Windows / Linux，Python 3.10–3.12，PaddlePaddle GPU 或 CPU，8GB 显存足够 |
| 典型耗时 | 电子 PDF（有文本层）**<0.5s/份**；扫描件/照片 GPU 约 **1–2s/页**，CPU 约 4–8s/页 |

## Steps（执行流程）

1. **确认输入**：文件或目录路径。目录会递归收集 PDF 与图片。
2. **环境自检**：`python scripts/env_check.py` —— 检查 Python 版本、PaddlePaddle、GPU、模型缓存。首次运行需联网下载模型（约 140MB，之后离线可用）。
3. **执行识别**：
   ```
   python scripts/run_ocr.py <输入路径> -o <输出目录>
   ```
   常用参数：`--type invoice|contract|receipt|generic` 强制类型；`--device cpu` 无 GPU 时；`--dpi 300` 提高扫描件精度；`--no-cache` 禁用缓存。
4. **读复核清单**：先看 `_review.md` 的 P0 项。**P0 未核对前，抽取值不得进入审计底稿。**
5. **交付下游**：把 `_index.json` 或单份 `.json` 交给对应的审计技能；`.md` 用于全文检索与 LLM 精读。

## 准确性设计（核心）

### 四层校验

| 层级 | 内容 | 失败标记 |
|---|---|---|
| L1 字符级 | OCR 置信度阈值（关键字段 0.90，一般 0.80） | `low_confidence:<字段>` |
| L2 格式级 | 统一社会信用代码 GB32100 校验位、发票号位数、日期合法性 | `checksum_failed` / `invoice_no_invalid` / `date_out_of_range` |
| L3 逻辑级 | 金额勾稽（不含税+税额=价税合计）、大小写一致、明细合计 | `arithmetic_mismatch` / `case_mismatch` / `items_sum_mismatch` |
| L4 跨文档 | 同批次发票号重复、税号对应名称漂移 | 写入 `_index.json` 的 `anomalies` |

### 质量分级

| 等级 | 含义 | 处理建议 |
|---|---|---|
| A | 必填齐全、勾稽通过、置信度达标 | 可直接使用 |
| B | 齐全但存在提示项（多金额候选、非关键低置信度） | 抽查后使用 |
| C | 勾稽失败 / 必填缺失 / 校验位不通过 | **必须人工核对** |
| D | 号码与日期均未抽到 | 仅作全文，不进结构化表 |

### 三条铁律

1. **只标记，不修正** —— 勾稽失败时绝不调整任一金额去凑平，只报告差额。
2. **无溯源即不可信** —— 每个字段带 `evidence{page, bbox, raw_text, source}`；无 evidence 的字段运行时视为不可信。
3. **抽不到就留空** —— 绝不用"同类发票的常见值"填充缺失字段。

## 关键实现细节

### 双引擎路径（性能核心）

| 输入 | 路径 | 耗时 |
|---|---|---|
| 电子 PDF（有文本层） | **直读文本层**，不渲染图片、不跑 OCR | <0.5s/份 |
| 扫描 PDF / 照片 | 渲染 → OCR 检测+识别 | 1–2s/页（GPU） |

文本层路径的准确率是 100%（不存在识别误差），电子发票、电子合同一律走这条。程序自动判断，无需人工指定。

### 发票金额抽取：表头列对齐

发票表格有「金额」「税额」「单价」等列名，与数据行的标签冲突。单纯按标签匹配会把「单价」的值当成「税额」。
本技能先定位表头行，按 x 坐标建立列映射，再按列取「合计」行的值 —— 实测可消除该类错误。

### 重复页与页眉页脚

- 扫描重复进纸、PDF 合并重复 → 自动检测并剔除（Jaccard 相似度 ≥0.85）。
- 多页文档的页眉页脚 → 只在每页首尾行中检测重复，正文中部不误删。
- **首页标题区永不剔除** —— 否则文档标题会被当成页眉删掉。

### 已知局限（务必知晓）

| 局限 | 说明 | 应对 |
|---|---|---|
| `‰` 常被 OCR 识为 `%` | 违约金日万分之几会被读成百分之几，差 10 倍 | 输出 `daily_rate_note` 提示核对原件 |
| 手写体识别率低 | PP-OCR 以印刷体为主 | 手写内容需人工录入 |
| 印章不识别内容 | 只判断有无印章区域，不认印章文字 | 印章真伪需另行核验 |
| 复杂合并单元格表格 | 列对齐可能错位 | 检查 `items` 后人工修正 |
| 合同条款不做语义判断 | 只切分结构，不判断"是否为固定总价合同" | 语义判断交给下游技能或人工 |

## 与下游技能的接口

| 下游技能 | 消费内容 |
|---|---|
| `s-1-revenue` P05 收入确认与 CAS14 专项 | 合同 `clauses`、`key_terms.payment` |
| `s-1-revenue` P06 抽样双向测试 | 发票 `fields`、`items` |
| `s-1-revenue` P07 截止测试 | 发票 `invoice_date`、合同 `meta.sign_date` |
| `z-2-accounts-receivable` | 合同 `parties`、账期 |
| `f-4-accounts-payable` | 发票 `seller_name`、`total_amount` |
| 任意技能 | `_index.json` 做批次检索 |

## 环境准备

```bash
# 1. 建虚拟环境（Python 3.10–3.12）
python -m venv ocr-venv

# 2. 装 PaddlePaddle（GPU 版，按 CUDA 版本选源）
pip install paddlepaddle-gpu==3.4.0 \
  --index-url https://www.paddlepaddle.org.cn/packages/stable/cu129/

# 3. 装 PaddleOCR 与 PDF 支持
pip install paddleocr==3.7.0 pymupdf

# 4. 自检
python scripts/env_check.py
```

首次识别会自动下载 PP-OCRv6 模型（约 140MB）到 `~/.paddlex/official_models/`，之后可完全离线运行。
