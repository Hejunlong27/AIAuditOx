## 六要素（技能工厂确认记录）

| 要素 | 内容 |
|------|------|
| 审计目标 | 完整性（C）：所有研发支出均已记录（含未列示于账面者）；存在（E）：记录的研发支出于资产负债表日存在且归被审计单位拥有或控制；准确性（A）：金额正确计算、适当加总且准确记录；列报（P）：分类、披露恰当 |
| 所需资料 | 研发支出/研发费用明细账、总账与报表、研发项目立项与预算、董事会/管理层决议、可行性研究报告、开发阶段资本化条件证据、工时/领料/试验记录、采购与付款凭证、验收/结项资料、财务报表附注 |
| 所需数据 | 研发项目、研究/开发阶段、本期投入、人工/材料/折旧/委外等构成、资本化金额、费用化金额、结转金额、截止日前后凭证、项目进度、预期经济利益、技术可行性证据 |
| 核对逻辑 | 1. 研发支出明细表编制与核对（获取或编制研发支出/费用明细表，复核加计是否正确，并与研发支出/费用总账数和明细账合计数核对是否相符，并将所属的“资本化支出”、“费用化支出”明细账期末余额与报表数核对是否相符。）；2. 研发支出增加检查（检查研发支出的增加）；3. 研发支出减少与结转检查（检查研发支出的减少）；4. 研发支出截止测试（对研发支出实施截止测试，检查资产负债表日前后天内开发支出明细账和凭证，确定有无跨期现象。）；5. 研发支出资本化条件与内容合理性检查（应关注研发支出的内容是否合理，研发支出资本化的依据是否充分，具体包括：（1）检查被审计单位对研究阶段和开发阶段的确认时点是否合理，研究阶段支出是否全部费用化；）；6. 研发支出披露检查（检查开发支出/费用相关财务报表附注披露的准确性和完整性。） |

## Steps（助理调度流程）

1. 确认项目工作目录已由项目经理指定（未指定则拒绝启动，升级项目经理）；在 `02_工作底稿/Z-25研发支出/` 下基于模板创建工作簿副本。
2. 校验输入资料完整性（见六要素「所需资料」）；缺失时向项目经理列明缺口清单并挂起。
3. 按依赖顺序分派实习生程序：P01 → P02 → P03 → P04 → P05 → P06；人工程序标记待办并跟踪完成状态。
4. 每个程序卡执行遵守「副本先行」：修改任何既有底稿前先创建副本入 `.auditox_backups/`；底稿每次生成/修订同步更新同路径「底稿名称+修订记录」.md。
5. 异常激活：按各程序卡「升级路径」处理，发现异常事项逐级升级。
6. 汇总各程序卡产出至工作簿，执行一级复核（见下方复核清单），复核通过后提交人工二级复核。

## 一级复核清单（助理执行，独立于编制上下文）

- 完整性：P01~P06 计划实施的程序均有底稿或「不适用+理由」记录；索引号连续无缺。
- 勾稽：明细表合计数 = 总账数 = 报表数；底稿间交叉索引正确。
- 证据充分性：每项结论可回溯到数据源；差异事项均有解释与支持文件。
- 异常闭环：所有异常事项有处理结果记录；未回函/回函差异已实施替代程序。
- 制式合规：每张底稿四段式结构完整，表头七要素齐全，修订记录同步。

## 边界与禁止事项

- 允许操作范围：仅项目工作目录内文件；仅调用 file_ops（读/写/改/格式）、数据核对脚本、Excel 计算。
- 禁止：物理删除任何文件（删除一律移入可恢复区）；向项目目录外发送客户数据；代替人工执行函证寄发/跟函/监盘动作；修改原始资料目录（01_原始资料 只读）；跳过强制程序。
- 数字核对一律使用脚本精确匹配，禁止以模型估算代替；差异原因说明可用模型起草，但必须标注「待人工确认」。

## Pitfalls

- 研究阶段支出或无法区分阶段的支出被资本化，导致资产和利润高估。
- 开发阶段五项资本化条件缺乏证据，特别是技术可行性、完成意图、产生经济利益方式和可靠计量。
- 研发人员薪酬、折旧、材料领用分配不当，可能虚增研发费用或资本化金额。
- 资产负债表日前后研发支出跨期，或已达到预定用途未及时转无形资产。
- 研发费用加计扣除口径与会计口径不同，税务资料不能替代会计审计证据。
