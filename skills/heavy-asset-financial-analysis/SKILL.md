## 1. 用途

把重资产企业的**原始财务与经营资料**，加工成一份管理层能直接用的**财务分析结论 + 报告**。核心不是"算指标"，而是回答五个问题：

> **公司现在怎么样 → 为什么这样 → 未来会怎么样 → 最大的风险是什么 → 应该怎么办。**

服务对象：房地产开发、城市更新/土地开发、矿产资源/矿山、能源、基础设施、工程建设、产业园区及其他重资产企业。

本技能是**总控**：识别任务 → 拆解 → 路由 → 汇总 → 交付。具体计算由 6 个子技能承担。

## 3. 铁律（违反即回退重做）

1. **先数据、后分析**。没看到数据不下结论。没有数据就写「**暂无数据，无法判断**」，禁止用行业常识或记忆数据填充。
2. **先通用、后专项**。先确定企业整体财务状态，再进入房地产/矿业专项。
3. **经营与财务必须结合**。禁止只分析财务报表；有经营台账（销售/回款/产量/成本/储量）时必须做交叉验证。
4. **现金流优先**。分析顺序固定为 **现金 → 债务 → 资产 → 利润 → 增长**，禁止只看利润。
5. **异常优先**。发现异常变动（>20% 或与经营逻辑相悖）先调查原因，再谈其他。
6. **结论必须有数据链**。每个重大判断须能还原为：**数据 → 指标 → 趋势 → 原因 → 风险 → 结论**。
7. **事实 / 判断 / 风险 三分**，不得混写：
   - 事实：「2025 年末有息负债 100 亿元，同比 +25%。」
   - 判断：「债务增速明显高于收入增速，杠杆扩张较快。」
   - 风险：「若经营现金流无法同步增长，再融资压力将进一步上升。」
8. **单位与口径先统一再比较**。万元/亿元、合并/单体、币种、期间不一致时不得直接对比。
9. **不编造、不美化**。拒绝为迎合用户而修改数据、拔高评级、隐去风险。外部行业基准必须标注来源与年份，无来源则标为「经验参考值」。

## 5. 路由决策

### 5.1 识别三件事

1. **企业类型**：房地产 / 城市更新 / 矿产 / 能源 / 基础设施 / 工程建设 / 产业园区 / 其他重资产 / 非重资产
2. **任务类型**：概览 / 三表 / 复盘 / 尽调 / 行业专项 / 债务 / 现金流 / 风险 / 汇报 / 报告
3. **输入资料**：Excel、CSV、PDF（财报/审计报告/附注）、Word、管理报表、项目明细、销售台账、回款台账、借款台账、生产台账、商品价格、预算/经营计划

### 5.2 路由规则

```
收到请求
   │
   ├─ 用户已明确点名某个子技能（"只分析房地产项目盈利能力"）
   │        └─→ 直接进入该子技能，不跑全流程（但先确认数据可用性）
   │
   ├─ 数据是原始/非结构化（PDF、台账、多份表）？
   │        └─ 是 → Skill 01（data-prep）
   │                └─ 数据缺口清单为空或已确认接受 → 继续
   │
   ├─ 需要整体财务判断？ ── 是 → Skill 02（statement-analysis）
   │
   ├─ 行业？
   │        ├─ 房地产/城市更新/产业园区 → Skill 03（real-estate）
   │        ├─ 矿产/矿山/能源（资源型） → Skill 04（mining）
   │        └─ 其他重资产 → 通用三表 + 资产质量 + 债务分析
   │                         并**明确声明**："该行业专项模型尚未覆盖"
   │
   ├─ 涉及债务、现金流、偿债、压力测试？ ── 是 → Skill 05（cashflow-debt-risk）
   │
   └─ 需要成文交付？ ── 是 → Skill 06（report-generator）
```

**强制联动**：凡进入 Skill 03 / 04，必须已跑过（或同批跑完）Skill 02；凡进入 Skill 06，必须已有 Skill 02 的输出，且默认带上 Skill 05 的风险评级。

### 5.3 三种工作模式

| 模式 | 适用 | 执行链路 | 交付形态 |
|---|---|---|---|
| **A 快速分析** | 高层会议、快速了解 | 01（轻量：只做口径统一与关键校验）→ 02 核心 → 05 摘要 | ≤1 页：5 条核心结论 + ≤15 个关键指标 |
| **B 标准分析** | 月/季/年度分析、经营复盘 | 01 → 02 → 03/04 → 05 → 06 | 标准财务分析报告（12 章） |
| **C 深度尽调** | 投融资、并购、债务排查 | 01（全量质检 + 勾稽复核）→ 02 → 03/04 → 05（6 情景压力测试）→ 06 | 深度尽调报告 + 全部中间产物 |

**模式选择规则**：用户明示"快速/一页纸/简单看看"→ A；明示"尽调/并购/投资/排查风险/审计报告"→ C；其余默认 **B**。数据量不足以支撑 C 时降级为 B 并说明原因。

## 6. 执行工作流

1. **建任务台账**：列出待办（数据整理 / 三表 / 专项 / 风险 / 报告），逐项推进。
2. **落盘与命名**：中间产物统一写入工作区 `fin-analysis/<公司简称>-<期间>/`，文件名见 `references/07-interface-contracts.md`。
3. **Skill 01**：产出标准化数据集、数据字典、质量报告、缺口清单、可计算/不可计算指标清单。
4. **确认缺口**：把缺口清单与降级方案一并告知用户，取得确认后再往下走（缺核心数据时不得静默跳过）。
5. **Skill 02**：五维分析 + 趋势（3 年 / 5 年 / 4 季，视数据）+ 财务质量背离识别。
6. **Skill 03 / 04**：按企业类型进入专项；两者互斥（同时含房开与矿业板块的混合集团，分板块各跑一次）。
7. **Skill 05**：现金流缺口 → 债务结构 → 期限墙 → 压力测试 → 风险评级（绿/黄/红）。
8. **Skill 06**：按模式选模板成文；先给"一句话结论"，再展开。
9. **自检**：对照第 8 节输出规范逐条核查后才交付。

## 8. 输出规范

任何交付物必须满足：

1. **结论先行**：开头给「一句话结论」+ 3–5 条核心判断，再展开论证。
2. **优先级排序**：分析优先级固定为
   **现金安全 > 偿债能力 > 资产质量 > 盈利质量 > 盈利规模 > 增长速度**。
3. **数据链完整**：重要结论后附 `数据 → 指标 → 趋势 → 原因 → 风险 → 结论`。
4. **标注来源**：每个关键数字标注来源类型（原始报表 / 用户提供 / 计算结果 / 推算结果 / 外部数据）。
5. **区分三分**：事实、判断、风险分别成段或成列，不得混写。
6. **口径与单位**：正文统一单位（默认万元，重大金额可并列亿元），开头声明合并/单体、币种、期间。
7. **缺口显性**：无法计算的指标集中列在"数据缺口"一节，写明缺什么、影响哪个结论。
8. **可落地建议**：建议必须具体到动作 + 责任方向 + 时间窗，禁止"加强管理"这类空话。

## 9. 错误处理

| 情况 | 处理 |
|---|---|
| 数据缺失 | 走降级路径，明确标注「该结论因缺少 X 数据未验证」；核心数据（资产/负债/收入/现金流）缺失时**暂停**并索取 |
| 文件无法解析 | 要求用户导出 CSV/Excel，或提供 PDF 对应页；不得凭文件名猜测内容 |
| 勾稽不平 | **先列差额，不强行调平**；差额 >1% 时标为数据质量风险并回溯来源 |
| 口径冲突 | 以用户指定口径为准；未指定时以合并口径为主、单体为辅，并在报告中声明 |
| 行业未覆盖 | 执行通用路径 + 明确声明行业专项模型未覆盖，不做行业特有推断 |
| 用户要求编造/美化 | 直接拒绝，并给出合规替代（如"用敏感性分析呈现区间"） |
| 数据量不足以支撑深度尽调 | 降级为标准分析，说明降级原因与缺失项 |

## 10. 反模式清单（禁止出现）

- 只有指标堆砌，没有经营解释。
- 只讲利润，不讲现金流与债务。
- 风险评级无数据依据。
- 用行业均值掩盖个体事实；用外部数据冒充企业数据。
- 报喜不报忧；对异常变动只描述不追因。
- 建议停留在"加强管理、优化结构"层面。

**用户**：「帮我分析这家房地产公司 2025 年的经营和财务情况，给董事长看。」

**总控动作**：
1. 识别 → 企业类型：房地产；任务：年度复盘 + 管理层汇报；模式：**B**（含管理层版本输出）。
