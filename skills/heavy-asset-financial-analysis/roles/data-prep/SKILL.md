# 角色 · 重资产财务数据整理与质量控制（Data Prep）

> 由顶层 `heavy-asset-financial-analysis` 在【环节 1 数据处理】调用。子技能 01。

## 1. 定位与适用场景

**定位**：把杂乱原始资料变成**唯一可信数据源**。本角色不产出分析结论，只产出"能不能分析、能分析到什么程度"。

**适用场景**
- 用户上传 Excel / CSV / PDF 财报 / 审计报告 / 财务附注 / Word 管理报表
- 用户上传台账：项目明细、销售台账、回款台账、借款台账、生产台账、储量报告
- 同一企业多份资料口径冲突、单位不一致、年份错位
- 用户说"数据有点乱，你先看看能不能用"

**不适用**：只有单一指标问询（如"毛利率多少"）——直接读表回答即可。

## 2. 输入

任意格式的原始资料，可能包括：
- 财务报表：资产负债表、利润表、现金流量表（单体/合并、多期）
- 审计报告、财务报表附注
- 管理报表、预算表、经营计划
- 台账：销售 / 回款 / 借款 / 项目 / 生产 / 储量 / 成本
- 外部数据：商品价格、区域房价

## 3. 输出

| 输出 | 内容 |
|---|---|
| `standard_dataset.json` | 标准数据集（Schema 见 `references/01-data-dictionary.md` §2） |
| `data-dictionary.md` | 本次实际用到的科目字典与口径说明 |
| `data-quality-report.md` | 12 条质量检查逐条结论 |
| `data-gap-list.md` | 数据缺口清单（缺什么 → 影响哪个结论） |
| 可计算指标清单 | 现有数据能算出哪些指标 |
| 无法计算指标及原因 | 哪些指标算不了、为什么 |

## 4. Instructions（执行步骤）

1. **清点资料**：列出收到的每个文件、格式、覆盖期间、口径，形成资料清单。
2. **提取数据**：优先取审计报告与附注；管理报表仅作补充。Excel/CSV 直接解析，PDF 按页定位报表。
3. **填 meta**：公司、行业、口径、币种、单位、期间列表、基准期、是否经审计、来源清单。
4. **单位归一**：全部折算为**万元**；面积→平方米；产量→吨。记录折算过程。
5. **科目归组**：按标准科目字典映射；无法映射的科目单列"未归组科目"。
6. **缺失处理**：缺失填 `null`，**绝不用 0 代替**；0 会被当作真实数值参与计算。
7. **溯源标注**：为每个关键字段填 `provenance`（文件名 + 页/表位置）。
8. **跑质检**：执行 12 条检查，或运行 `python scripts/data_qc.py --input standard_dataset.json --out data-quality-report.md`。
9. **出缺口清单**：明确列出缺失项、影响范围、可选替代来源。
10. **判定状态**：`qc.status` = `pass` / `warn` / `fail`。
    - 核心 4 类（资产 / 负债 / 收入 / 现金流）任一缺失 → `fail`，**停止下传**并索取数据。
    - 非核心缺失 → `warn`，继续但标注降级。
11. **向用户确认**：把缺口清单与降级方案一次性说清，等确认后再交给 Skill 02。

## 5. 计算逻辑（本角色只做校验性计算，不做分析）

| 校验 | 公式 | 判据 |
|---|---|---|
| 资产勾稽 | 资产合计 −（负债合计 + 所有者权益合计） | 差额/资产 > 1% → 质量风险 |
| 现金勾稽 | 期末现金 −（期初现金 + CFO + CFI + CFF） | 同上 |
| 利润勾稽 | 营业利润 −（收入 − 成本 − 税金 − 期间费用 + 其他损益） | 同上 |
| 期初期末衔接 | 本期期初 − 上期期末 | 不为 0 → 列差额，不调平 |
| 经营-财务匹配 | 收现比 = 销售商品收到现金 / 收入；产量 × 单价 vs 收入 | 偏差 >10% → 必须追因 |
| 数量级校验 | 收入 / 总资产、存货 / 总资产 等比率是否合理 | 异常 → 疑单位错误 |

## 6. 分析逻辑（质检优先级）

1. **可信度分层**：审计报告 > 财务报表 > 附注 > 管理报表 > 用户口头数据。
2. **冲突取用**：同一指标多来源冲突 → 并列展示，采用高可信度来源，其余标注差异。
3. **口径隔离**：合并与单体不得混用；如需对比，分别成表。
4. **不做推断**：缺失就是缺失，不插值、不补算、不用行业均值替代。
5. **可回溯**：任何进入标准数据集的数字，必须能指回原始位置。

## 7. 风险规则（本角色识别的是"数据风险"，不是经营风险）

| 编号 | 数据风险 | 触发 | 处理 |
|---|---|---|---|
| DQ-01 | 核心数据缺失 | 资产/负债/收入/现金流任一缺失 | `fail`，停止下传 |
| DQ-02 | 勾稽不平 | 差额 >1% | 列差额 + 回溯来源，标为质量风险 |
| DQ-03 | 单位疑误 | 比率数量级异常 | 回溯表头，禁止直接改数 |
| DQ-04 | 口径混用 | 合并/单体同表混用 | 分离成表 |
| DQ-05 | 期间错位 | 期初期末不衔接 | 列示并请用户确认 |
| DQ-06 | 来源缺失 | 关键字段无 provenance | 报告中标"来源待确认" |
| DQ-07 | 经营财务背离 | 收现比异常 / 产量×单价与收入偏差 >10% | 追因并记录 |
| DQ-08 | 科目未归组 | 存在无法映射科目 | 单列，评估是否影响指标 |

## 8. 示例任务

**输入**：用户提供「某矿业公司 2023–2025 审计报告 PDF + 2025 生产台账 Excel + 借款台账 Excel」。

**执行**：解析三表 → 填 meta（`industry: mining`、`unit: 万元`、`periods: [2023,2024,2025]`）→ 归组科目 → 标注 provenance → 跑质检 → 出缺口清单。

**发现的典型问题**（示例输出节选）：

```markdown
## 数据质量报告（节选）

### 勾稽检查
| 检查项 | 差额（万元） | 差额率 | 结论 |
|---|---:|---:|---|
| 资产 = 负债 + 权益（2024） | 0 | 0.00% | 通过 |
| 资产 = 负债 + 权益（2025） | 1,240 | 0.08% | 通过（<1%） |
| 期末现金 = 期初 + 三类现金流（2025） | 0 | 0.00% | 通过 |

### 经营-财务匹配
| 项目 | 财务口径 | 经营台账口径 | 偏差 | 结论 |
|---|---:|---:|---:|---|
| 2025 收入 | 186,000 | 产量 42 万吨 × 单价 4,850 元 = 203,700 | −8.7% | 差异在阈值内，疑年末库存未售，已记录 |

### 数据缺口清单
| 缺失项 | 影响结论 | 建议来源 |
|---|---|---|
| 可采储量与品位（分矿山） | 储采比、剩余服务年限、储量消耗率无法计算 | 地质储量报告 |
| 借款到期明细（2028 年以后） | 债务期限墙仅能覆盖至 2027 年 | 借款台账补充 |
```

## 9. 边界

- 只产出数据与质量结论，**不得给出经营或财务分析结论**。
- 不得修改原始文件（`00-raw/` 只读）。
- 不得为"让数据好看"而调平差额或补填缺失。
