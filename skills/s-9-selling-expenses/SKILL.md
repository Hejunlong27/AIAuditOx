## 六要素（技能工厂确认记录）

| 要素 | 内容 |
|------|------|
| 审计目标 | 完整性（C）：所有销售费用均已记录（含未列示于账面者）；存在（E）：记录的销售费用于资产负债表日存在且归被审计单位拥有或控制；准确性（A）：金额正确计算、适当加总且准确记录；计价（V）：按恰当金额计价（含减值、摊销、公允价值等调整）；列报（P）：分类、披露恰当 |
| 所需资料 | 销售费用明细表与明细账（含部门辅助核算）、销售部门人员与薪酬清单、固定资产折旧分配表、无形资产摊销表、佣金与广告宣传合同、业务招待费明细与审批记录、供应商清单、服务机构协议、报表附注 |
| 所需数据 | 各费用项目本期发生额与上年同期数、主营业务收入、预算数、同行业费用率、销售部门人数与薪酬、折旧与摊销分配金额、佣金奖金与销售收入的对应关系、税前扣除限额、实际执行的重要性水平 |
| 核对逻辑 | 1. 实质性分析程序（分析销售费用变动的合理性）；2. 销售费用明细表编制与核对（获取销售费用明细表）；3. 费用归集与勾稽关系检查（复核销售部门人工变动）；4. 应付未付销售费用截止检查（抽样检查应付未付销售费用）；5. 重点与异常费用项目检查（检查销售佣金支出）；6. 费用凭证抽样追查（从总账中选取费用样本并追查至供应商发票及收到的货物/服务）；7. 舞弊风险应对—供应商与发票重复性测试（舞弊—针对与费用相关的职责分离不充分的测试）；8. 服务机构费用检查（服务机构—费用）；9. 销售费用披露检查（审计销售费用的披露） |
| 底稿编制内容 | 见「产出清单」，全部底稿采用四段式制式：底稿名称与表头（项目基本信息）→ 审计目标和程序说明 → 审计程序执行结果 → 审计说明。共 9 张底稿。 |
| 输出格式 | xlsx 工作簿（模板见 templates/S-9销售费用审计工作簿模板.xlsx），每份底稿同路径伴随「底稿名称+修订记录」.md |

## Steps（助理调度流程）

1. 确认项目工作目录已由项目经理指定（未指定则拒绝启动，升级项目经理）；在 `02_工作底稿/S-9销售费用/` 下基于模板创建工作簿副本。
2. 校验输入资料完整性（见六要素「所需资料」）；缺失时向项目经理列明缺口清单并挂起。
3. 按依赖顺序分派实习生程序：P01 → P02 → P03 → P04 → P05 → P06 → P07 → P08 → P09；人工程序标记待办并跟踪完成状态。
4. 每个程序卡执行遵守「副本先行」：修改任何既有底稿前先创建副本入 `.auditox_backups/`；底稿每次生成/修订同步更新同路径「底稿名称+修订记录」.md。
5. 异常激活：按各程序卡「升级路径」处理，发现异常事项逐级升级。
6. 汇总各程序卡产出至工作簿，执行一级复核（见下方复核清单），复核通过后提交人工二级复核。

## 一级复核清单（助理执行，独立于编制上下文）

- 完整性：P01~P09 计划实施的程序均有底稿或「不适用+理由」记录；索引号连续无缺。
- 勾稽：明细表合计数 = 总账数 = 报表数；底稿间交叉索引正确。
- 证据充分性：每项结论可回溯到数据源；差异事项均有解释与支持文件。
- 异常闭环：所有异常事项有处理结果记录；未回函/回函差异已实施替代程序。
- 制式合规：每张底稿四段式结构完整，表头七要素齐全，修订记录同步。

## 边界与禁止事项

- 允许操作范围：仅项目工作目录内文件；仅调用 file_ops（读/写/改/格式）、数据核对脚本、Excel 计算。
- 禁止：物理删除任何文件（删除一律移入可恢复区）；向项目目录外发送客户数据；代替人工执行函证寄发/跟函/监盘动作；修改原始资料目录（01_原始资料 只读）；跳过强制程序。
- 数字核对一律使用脚本精确匹配，禁止以模型估算代替；差异原因说明可用模型起草，但必须标注「待人工确认」。

## Pitfalls

- 销售费用与管理费用的归集界限易混（如销售人员薪酬计入管理费用），须核对部门辅助核算与分配表
- 业务招待费、广告宣传费有税前扣除限额，超限部分须作纳税调整，勿只看账务处理是否正确
- 销售佣金应有合同与结算依据；仅凭发票入账的佣金须评估真实性与是否涉及商业贿赂
- 期末前后发生的广告投放、促销活动费用易跨期，须做截止测试并核对服务期间
- 「其他」类明细金额重大且无明细的，须要求管理层拆分，否则无法验证性质
- 费用与收入变动趋势长期背离可能是收入造假或费用跨期的信号，勿仅作说明性结论
